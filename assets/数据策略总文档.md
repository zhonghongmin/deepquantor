## 1. 宏观策略

> 宏观层唯一职责：**把宏观环境翻译成"该拿多少仓、偏向什么风格、股债金现金怎么分"**。它不预测个股，只定总风险预算与风格基调。

### 1.1 目标与定位

| 项    | 定义                                                                                                                                                                   |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 输入   | 中国 + 国际宏观指标（数据层 §2.1），取**最新可得值 + 趋势方向**                                                                                                                              |
| 输出   | `equity_weight`（权益仓位中枢）、`style_tilt`（风格偏好）、`asset_alloc`（大类资产配置）、`regime`（周期象限）、`phase`（前期/后期）、`phase_progress`（相位进度）、`money_credit`（货币信用组合）｜**状态机+查表+相位插值产出，无因子评分** |

**排期约束**（惯例日，实际以官方日程为准）：

- 周期判定只用月频量；DR001 按 D-18 只作辅助信号、不改主判定。
- 发布日程依据统计局《主要统计信息发布日程表》及央行 / 海关 / 外管惯例；引擎每年初抓一次当年日程落库、每日校验「是否已发布」，**不得按惯例日硬编码取数**。

### 1.3 宏观状态分类（规则判定 + 因子分微调）

> 宏观做三件事：① 规则把宏观数据分成离散状态；② 状态→配置查表（§1.4）得基准仓位；③ 宏观因子评分对基准仓位有界微调（§1.17），**不改变象限**。判定本身不含拟合，但**每个因子与每格配额都要过回测闸门**（§1.18）才保留——宏观做的是时序验证，不是横截面排序（§4.1）。  
> **两个「两层」不同**：预判—验证分层回答「数据可不可用」（§1.3.0）；判定分层回答「谁定方向、谁定细化」——货币 / 信用为**领先层**（§1.3.3 / §1.3.4），增长 / 通胀为**确认层**（§1.3.1 / §1.3.2）。小节编号按数据脉络排布，不代表判定次序。

每个因子组给出一个**离散状态**（扩张 / 中性 / 收缩 或 宽松 / 中性 / 收紧），取值 ∈ {+1, 0, −1}。

#### 1.3.0 数据可得性与「预判—验证」分层

> 宏观各指标**发布节奏差异极大**，若不分层，滞后最久的 GDP 会成为当期判定的短板。因此四因子按「可得时点 + 是否修订」分为两层：

| 层级                | 用途                               | 指标                                                                   | 最早可得                     | 是否修订             |
| ----------------- | -------------------------------- | -------------------------------------------------------------------- | ------------------------ | ---------------- |
| **预判层 Nowcast**   | **决定当期 `regime` / `phase` / 仓位** | PMI、CPI、PPI、M1/M2、社融与信贷、**DR001（日频，唯一口径）**                           | 当月月末 ~ 次月 15 日（价类指标当日可得） | 基本不修订            |
| **验证层 Confirmed** | **事后验证 PMI + 展开增长细项，不改变当期状态**    | GDP（季频）、工业增加值、固定资产投资/社零/地产、工业企业利润、进出口（外需）——**增长组除 PMI 外均为验证层**（§1.2） | 季末 / 次月 15~27 日          | GDP 多次修订；其余基本不修订 |

**三条运行规则**：

1. **当期只读预判层**：`classify_growth` 的**主判据为 PMI**（及趋势），**GDP 不参与当期 ±1 判定**；`classify_inflation` 主判据为 CPI + **PPI 领先方向**。
2. **GDP 到点即校验（verify）**：GDP 首发后，将过去 1–2 季的 `regime` 与 GDP 实际值对照——若 PMI 给出的增长状态与 GDP 方向**背离**（如 PMI 连续 >50 但 GDP 同比 <3%，或反之），标记 `data_quality = divergence`，**下调 `confidence`** 并触发人工复核，但**不追改历史信号**（避免未来函数）。
3. **GDP 用于远期锚定（anchor）**：季度 GDP 决定「中期增长中枢」的上下限，供 §1.4 强度规则与 §1.5 风格判断的**年度视角**参考（如 GDP 中枢下台阶 → 长期压低权益中枢），不参与月度仓位微调。

#### 1.3.1 经济 / 增长 Growth（PMI 主导，GDP 降为验证）

| 判定      | 规则（**预判层：仅 PMI**）                                   |
| ------- | --------------------------------------------------- |
| 扩张 (+1) | PMI（制造业 3 月均）**> 50.5** 且趋势向上/持平；或连续 3 月 > 50 且环比不降 |
| 中性 (0)  | PMI 3 月均在 **49.5 ~ 50.5** 之间（荣枯线附近震荡）               |
| 收缩 (-1) | PMI（3 月均）**< 49.5** 且趋势向下；或连续 3 月 < 50 且环比走弱        |

**GDP 恒为验证层**：不参与当期判定与相位驱动，仅事后校验：一致则上调一档 `confidence`，背离则下调一档并审计；并作年度增长锚 `gdp_anchor`。规则见 §1.3.0。

#### 1.3.2 通胀 Inflation（含 PPI→CPI 传导预判）

**PPI → CPI 存在 3–6 个月的传导时滞**（上游成本 → 中游加工 → 下游消费品），因此**用 PPI 的当前方向预判 CPI 的未来方向**，而非等 CPI 自己走完。

| 判定      | 规则                                                                   |
| ------- | -------------------------------------------------------------------- |
| 下行 (-1) | CPI 同比 < 1% 且趋势向下；**或** PPI 同比 < 0 且连续下行（成本端通缩，**预判** 3–6 月后 CPI 承压） |
| 温和 (0)  | CPI 同比 1%–3% 且趋势平稳；**且** PPI 未出现加速上行/深度负值                            |
| 上行 (+1) | CPI 同比 > 3%；**或** PPI 同比快速抬升：3 月累计涨幅 > 1pct 即成本端过热，预判 CPI 滞后跟上       |

**传导预判的两种典型背离（须显式处理）**：

| 情形               | 现象                 | 处理                                                          |
| ---------------- | ------------------ | ----------------------------------------------------------- |
| **PPI 上、CPI 未上** | 上游涨价、下游需求弱，传导不畅    | 判 `上行偏早`：记 +1 但 `confidence=中`，风格偏上游资源，标注 `ppi_cpi_gap=扩张`  |
| **PPI 下、CPI 仍高** | 成本回落但终端价格黏性（服务/食品） | 判 `下行偏早`：仍记 -1 但 `confidence=中`，标注 `ppi_cpi_gap=收敛`，不急于大幅加仓 |

**不构成未来函数**：只用已发布的 PPI 方向推断 CPI 的可能走向，用于提前调整 `confidence`、风格倾斜（§1.5）与相位插值（§1.4），**不修改当期 CPI 读数、不虚构未发布数据**。

#### 1.3.3 货币 Money（量定档，DR001 只作辅助信号）

**量（唯一主判）**：`M2 同比` = 货币总量；`M1−M2 剪刀差` = 活化度。`factors.money` 完全由量决定，不设强弱档、不设量价四象限。

| 量（M2 / M1 活化 · 唯一主判） | `factors.money` | 含义                | DR001 辅助预警（不参与判定）                      |
| -------------------- | --------------- | ----------------- | -------------------------------------- |
| 上行 / 活化改善            | **+1**          | 宽货币：放水且活化跟上，权益最友好 | 价上行 → `credit_derived_suspect`（疑似信用派生） |
| 平稳                   | **0**           | 货币量持平，维持上期基调      | 价持续下行 → `policy_easing_lead`（传导前段预警）   |
| 下行 / 活化恶化            | **−1**          | 紧货币：水量收缩，防御       | 价下行 → `demand_weak_suspect`（疑似需求端萎缩）   |

**货币价只取 DR001**：日频采集（中国货币网 / 外汇交易中心）落库；`warn_flags` 产出随 D-30 后移。

| 候选口径                                  | 是否采用        | 原因                                            |
| ------------------------------------- | ----------- | --------------------------------------------- |
| **DR001**（水平 + 趋势）                    | ✅ 唯一口径（仅辅助） | 央行已定为调控目标利率；曲线最短端、不含期限风险；日频当日可得、不修订           |
| DR007 / 期限价差 / 银行—非银分层                | ❌ 不采集       | 央行已改用 DR001 为代表性利率；对辅助预警无增量信息，多一条日频依赖即多一类断链风险 |
| 政策利率锚 / 走廊 / NCD / MLF / LPR / 10Y 国债 | ❌ 不采集、不作货币价 | 政策利率是「锚」不是「松紧度」；10Y 不采集（中美利差属外生 Overlay，D-30 后移）            |

> **铁律（D-18）**：DR001 不参与任何判定环节——不作 `classify_money` 入参、不写 `money_detail`、不调强弱档、不改 `confidence`、不改风格。`dr001_pctile ≥ 95% / ≤ 5%` 仅记 `dr001_extreme=true`（以 20 日均值复核技术性时点），不单例翻转状态；量升价升仍判 `+1` 并落 `warn_flag=credit_derived_suspect`。央行若改变调控框架须重新评审本节，不换锚。

#### 1.3.4 信用 Credit（社融 + 贷款 → 宽信用 / 紧信用）

只看**水流进实体多少**：**社融（总量口径）+ 贷款（企业中长贷）两项主判据**，不看任何价格（价格属货币端 §1.3.3；长端国债不属本状态机）。

| 判定       | 规则（**仅两项主判据**）                           |
| -------- | ---------------------------------------- |
| 宽信用 (+1) | **社融存量同比趋势上行** **且** **新增企业中长贷同比多增**     |
| 中性 (0)   | 社融同比与企业中长贷近 3 月变动均小于阈值（平稳）；或两项背离且幅度均在阈值内 |
| 紧信用 (-1) | **社融存量同比趋势下行** **或** **企业中长贷同比少增**       |


- **两项权重**：默认「**社融定方向、贷款定确认**」——社融是实体融资总盘子（含贷款/债券/表外），企业中长贷最反映实体扩张意愿。两者**同向**信号最清晰；**背离**时（社融上行但中长贷少增 = 靠政府债/票据冲量）默认降为 `0` 并置 `confidence=中`，**不得强行判 ±1**（§1.12 假设 12）。
- **可选观察（不参与判定）**：`社融 − M2 剪刀差`（上行 = 水流向实体、持续下行 = 淤积"推绳子"）只作视角，不是第三判据，**不得翻转 `factors.credit`**。
- **不设「货币→信用」传导验证层**：传导结果已在社融与中长贷直接观测，再加「企业贷款加权利率」只引入季频滞后（季后 30–45 天）、无 API、口径修订三重噪声，零增量；货币与信用是否脱节由 `money_credit` 组合（如「宽货币紧信用」= 推绳子）直接表达（§1.4）。美元流动性与地缘政治不属本状态机，本期不引入（外生 Overlay 随 D-30 后移）。

### 1.4 周期定位与基准仓位（状态空间 × 配置查表）

> **流水线**：象限 × 九态交叉命中 **36 格基准带**得权益仓位中枢；象限「后期」沿时钟线性插值（下文①），翻转瞬间零跳变。宏观**不做**无约束连续加权拟合——低频滞后大，直接拟合「最优仓位连续函数」只会过拟合；仓位以状态区间表达、仅状态切换才调仓，其上仅允许叠加有界因子微调（§1.17，幅度受 κ 硬约束）。

**领先层｜货币 × 信用 → `money_credit` 九态（定基调，不定象限）**

货币量与信用量各三档（宽 / 中性 / 紧），与 §1.3.3 / §1.3.4 一一对应：

| 货币＼信用 | 宽信用 (+1) | 中性信用 (0) | 紧信用 (−1) |
| --- | --- | --- | --- |
| **宽货币 (+1)** | 双宽｜**进攻** | 宽货币·中性信用｜**中性偏多** | 宽货币紧信用｜**中性偏多** |
| **中性货币 (0)** | 中性货币·宽信用｜**中性偏多** | 中性·中性｜**中性** | 中性货币紧信用｜**谨慎** |
| **紧货币 (−1)** | 紧货币宽信用｜**谨慎** | 紧货币·中性信用｜**谨慎** | 双紧｜**防御** |

> 基调随货币档走（宽→偏多 / 紧→谨慎 / 双中性→中性），信用档只做加减；任一维度取 0 即翻到对应九态名，不沿用上期。「宽货币紧信用」为推绳子型（水淤积在银行体系），只落 `warn_flag=credit_derived_suspect`、不改分类（§1.3.3、D-18）。
> **两维不可混用**：`money` 只看量（§1.3.3），`credit` 只看社融与贷款（§1.3.4）。M2 高增 + 社融弱 + 中长贷少增 = 宽货币紧信用（推绳子），不得判双宽。
> **降级运行**：仅 M1/M2 + 社融 / 中长贷齐备（次月 10–15 日）即可输出 `money_credit` 与基调，象限沿用上期、`confidence` 降一档；DR001 不进降级依赖集。

**领先性边界与确认规则**

> **① 范畴隔离**：`money_credit` 是输入（政策与金融条件），`regime` 是输出（增长 + 通胀结果），因果链非一一映射。接口、UI、文案禁止用周期名命名九宫格，禁止由 `money_credit` 反推 `regime`。
> **② 双宽 ≠ 复苏**：36 格中「双宽」同时存在于复苏 90 / 过热 71.5 / 滞胀 41.5 / 衰退 62.5 四行；把「衰退 + 双宽」误标为「复苏 + 双宽」将多配 **27.5pct** 权益。`regime` 升级为复苏须同时满足：PMI 连续 ≥2 期站上荣枯线并按 §1.3.1 判扩张、企业中长贷同比多增（剔除政府债 / 票据冲量）、连续期数 ≥3。未满足前 `regime` 保持上期，取区间下沿 + 降 `confidence`，UI 展示「政策发力 · 待经济确认」。本规则只改置信度与区间取位，不改 36 格数值。
> **③ 测试断言**（实现见《系统设计总文档》§9）：T-1 `mc=双宽, 增长=收缩` → `regime=衰退`、`equity_weight_base=62.5%`、`confidence` 降级；T-2 九宫格九格标签不得含周期名；T-3 下游不得由 `money_credit` 推导 `regime`；T-4 未确认态副标签仅在背离或降档时出现。

**确认层｜经济 × 通胀 → 四象限 + 相位**

| 增长＼通胀 | 下行 (-1) | 温和 (0) | 上行 (+1) |
| --- | --- | --- | --- |
| 扩张 (+1) | **复苏** | 复苏 | **过热** |
| 中性 (0) | **复苏** | 复苏 | **过热** |
| 收缩 (-1) | **衰退** | 衰退 | **滞胀** |

→ **周期只有四个：复苏 / 过热 / 滞胀 / 衰退**。经济 × 通胀 3×3 九格全部归入四象限，不设第五状态；方向未定的过渡由 `前期 / 后期` 相位承担。

归并规则（纯函数，同输入同输出）：`inflation=+1` → 增长收缩判滞胀、否则过热；`inflation≤0` → 增长收缩判衰退、否则复苏。中性行归并后一律 `phase=前期`、`phase_progress=0`，配额按目标格整行执行、不折减。

> 温和通胀下的扩张判「复苏」而非「过热」，为设计默认——过热须通胀确认（§1.12 假设 6）。

**相位（插值参数，不扩表）**

每个主象限再按所处阶段分**前期 / 后期**。**查表只有 36 格，相位不扩大查表空间，只作插值参数**：

- 取该象限「**驱动下一翻转的变量**」的连续水平（下表），做**滚动窗口 min-max 归一化**得 `phase_progress ∈ [0,1]`；`< 0.5 → 前期`，`≥ 0.5 → 后期`；**四象限均有相位**，中性区归并后固定取 `phase=前期`、`phase_progress=0`，过渡由相位插值承担。
- 驱动变量**一律取预判层**：增长用 **PMI**、通胀以 **PPI 为主**（PPI 领先 CPI 3–6 月，更早反映拐点）；**GDP 不作相位驱动**（季频 + 滞后 + 修订 → 相位长期滞后与历史漂移），仅作 `gdp_anchor` 年度锚定（§1.3.1）。

| 主象限 | 驱动变量（连续水平，**均取预判层**） | 含义 |
| --- | --- | --- |
| 复苏（增长+ / 通胀-） | 通胀水平（**PPI 同比为主、CPI 为辅**） | 通胀自谷底回升的进度（PPI 领先翻正 → 转过热） |
| 过热（增长+ / 通胀+） | 增长水平（**PMI 为主**，GDP 仅作年度锚） | 增长沿上行腿推进、临近见顶的进度（临近回落 → 转滞胀） |
| 滞胀（增长- / 通胀+） | 通胀水平（**PPI 同比为主、CPI 为辅**） | 通胀自峰位回落的进度（临近翻负 → 转衰退） |
| 衰退（增长- / 通胀-） | 增长水平（**PMI 为主**，GDP 仅作年度锚） | 增长自谷底回升的进度（临近翻正 → 转复苏） |

> **落库约束（衔接数据层）**：PMI / CPI / PPI 的**连续水平（level）须原样保留**，落库不得被二值化 / 分类截断，否则无法计算 `phase_progress`；归一化窗口 `W`（默认 24 个月）与变量选择见 §1.12 假设 6。**相邻象限驱动变量不同（PMI↔PPI），`phase_progress` 在翻转点不跨象限可比，仓位连续性由下文①的插值断言保证**。`phase_progress` 仅作相位划分与插值权重，**不作为因子评分输入**，宏观因子评分口径见 §1.17，`phase_progress` 不进入 `s_i`。

**落格前同月校验（D-24 · 判定层，不改配额）**：36 格须由同一 `period` 的两层观测联合定位——`vintage.pmi_month` / `cpi_month` / `ppi_month` 与 `money_detail.month` / `credit_detail.month` / `macro_detail.month` 六处全等；不一致即拒绝出 36 格，只走方向模式并标 `period_mismatch`。四类指标同属 M 月但可得日不同，完整两层判定最早在 M+1 月 15 日闭合；`publish_date ≤ signal_date` 与 `vintage` 快照保证无未来函数（§1.3.0）。在线 36 格是同月共现，不是「M 月货币信用 → M+3 月经济通胀」的预测配对；领先性只在 §1.15 离线检验。

**① 相位过渡倾斜（平滑切换）**

时钟顺序 **复苏 → 过热 → 滞胀 → 衰退 → 复苏**；象限「后期」按 `phase_progress` 向时钟下一象限线性插值：

```
# center(regime, mc) 取上表中值；next(regime) 取时钟后继
w_base = center(regime, mc)                          # 前期：维持中枢
if phase == "后期":
    p = clamp((phase_progress - 0.5) / 0.5, 0, 1)    # 后期内归一化进度
    w_eff = center(regime, mc) + p * (center(next(regime), mc) - center(regime, mc))
else:                                                # 前期
    w_eff = center(regime, mc)
# 四象限均有相位；中性区归并后固定 phase=前期 / phase_progress=0
```

**平滑性**：后期末端 `phase_progress → 1` 时 `w_eff → center(next, mc)`，翻转后进入下一象限前期即取 `center(next, mc)`，两端相等故零跳变。例：复苏后期双宽由 90 降至 71.5，翻转至过热前期即 71.5；衰退后期双宽由 62.5 升向 90，翻转至复苏前期即 90。

> 此 `w_eff` 即 **`equity_weight_base`**（经相位倾斜后的基准仓位）。插值中货币信用组合**保持不变**（仅象限沿时钟滑动），故仍属「查表 + 区间中值」框架，未引入任何连续因子评分。

**② 相位倾斜下的再分配规则**

```
ratio = (100 - w_eff) / (100 - center_stock)
bond' = bond × ratio
commodity' = commodity × ratio   # 本期恒为 0.0（占位），缩放后仍为 0.0
gold' = gold × ratio
cash' = cash × ratio
```

> 相位倾斜只改变「股 / 非股」比例，不改变非股四类的内部结构。

**③ 边界与约束**

- 五项均为百分比、`≥ 0`，合计恒为 100%；`stock == equity_weight`（基准 + §1.17 有界微调）。
- **校验断言**：五项合计 ≠ 100%、缺失 `commodity` 字段、或本期 `commodity ≠ 0.0` → 抛错。
- **`gold` 舱**为目标风险预算额度，本期无实际标的、不实盘下单，对应资金暂以货币资金持有；外生 Overlay 危机态上调随 D-30 后移。字段名沿用 `gold` 兼容历史快照与下游表结构，中文类名为「贵金属」。

### 1.8 与中观 / 微观的衔接

```
宏观基准输出 ──┬─► equity_weight_base ──┐
              ├─► style_tilt ──────────┤
              └─► asset_alloc_base ────┤
                                       ▼
              （外生风险 Overlay：本期后移 · D-30，恢复后插此层）
                                       │
                                       ▼
        实际 equity_weight / asset_alloc（跨层风险闸门）→ 中观/微观
```

- **中观（§2）**：除仓位与风格外，还接收 **`macro_detail`**——CPI、PPI、进出口分项 up/down 清单（§1.2.2）——作为景气拆解（§2.2.0）的直接输入——只用于行业级拆解，不得反推宏观状态。
- **中观（§2）**：**先受 `equity_weight` 总预算与 `style_tilt` 白名单双重约束**，再在五年规划行业池内对申万一级行业打分，非白名单 / 池外行业降权；`equity_weight` 决定行业 ETF 核心仓的总预算。
- **微观（§3）**：选股池受 `style_tilt` 约束（如滞胀态下优先防御属性个股），个股卫星仓权重合计 ≤ `equity_weight` 留给卫星的部分。

**测试覆盖要求**

- `map_*` / `locate_*` / `interpolate_*` 每个函数须有全状态空间参数化测试：**36 格逐格与 §1.4 基准带一致**，叠加相位端点断言（`phase_progress ∈ {0, 0.5, 1}` × 36 格）；插值函数覆盖后期全区间。

- `run_macro` 须有反例断言：双紧 + 滞胀 → `equity_weight_base ≤ 0.45` 且 `cash > 0`。

**预判—验证隔离测试**：
- **滞后隔离断言**：构造「GDP 极差但 PMI 强扩张」的数据集，`run_macro` 输出的 `factors.growth` 必须为 `+1`（由 PMI 决定），且 `vintage.data_quality=divergence`、`confidence` 相对基准下调一档；
- **无 GDP 可跑通**：仅提供 PMI/CPI/PPI/M1M2/社融，`run_macro` 必须正常输出，`vintage.nowcast_only=true`、`data_quality=preliminary`；
- **相位不漂移**：同一交易日、同一 PMI/PPI 序列，在「GDP 尚未发布」与「GDP 已发布（含修订）」两种状态下，`phase_progress` 与 `equity_weight_base` **必须完全相同**（证明 GDP 不污染当期相位）；

**宽货币 / 宽信用口径测试（D-18）**

- **量价隔离**：M2 高增 + DR001 上行 + 社融下行 → `money=+1`、`credit=-1`、`money_credit=宽货币紧信用`，`warn_flags` 含 `credit_derived_suspect`，`confidence` 与「仅由量判定」基准用例逐字段一致。

#### 1.15.1 预测信号（领先窗口 · 双窗口并列）

- **禁止前视**：预测信号只能用 `as_of` 时点**已发布**的数据； 不虚构未发布读数、不修改当期 CPI / PPI 实际值（§1.3.2「预判不等于预测未来函数」）。
- **展示副本**：预测结果**不写回** `macro_signal` 任何字段， 不参与 `regime` / `phase` / `asset_alloc` / `equity_weight` 计算； §1.3.2 中「提前调整 confidence / 风格倾斜 / 相位插值」属**主判定内部既有逻辑**， 页面展示的预测信号是它的只读投影，两者不得互相覆盖。
- **命中率**：首期一律标注「待回测」，**不得伪造数值**； 待 M1 回测固化后按 `signal_id × lead_window` 登记历史命中率，并随预测偏差滚动更新。
- **失效条件必须显式**：每条信号须带失效条件；触发失效时降为「参考级」并标注原因，不得静默保留原方向。

**双窗口口径（D-20）**：短窗（1–2 月）与长窗（3–6 月）并列展示，不修改 §1.3.2 的阈值与档位（阈值须 M1 回测固化后调整）。中国 PPI 与 CPI 通常同月发布，「预测」指用 PPI 已发布方向推断未来 CPI 读数方向，不是提前取得未来值。

| 窗口 | 传导链 | 依据（只取已发布数据） | 领先期 | 置信 / 命中率 | 失效条件 |
| --- | --- | --- | --- | --- | --- |
| **短窗** | 高频工业品 / 大宗 → PPI → CPI 近端 | 工业品指数、铜金比、开工率（日 / 周频）+ 最新已发布 PPI | **1–2 个月** | 参考级；命中率**待 M1 回测** | 输入性油价冲击、下游需求塌陷、传导不畅 |
| **长窗** | PPI → CPI 成本传导（§1.3.2） | PPI 同比方向（连续 3 月累计涨幅 > 1pct 等，最新已发布期） | **3–6 个月** | 中 / 高按 §1.3.2；命中率**待 M1 回测** | `ppi_cpi_gap=扩张`（PPI 上 / CPI 未上）、猪价下行、服务价格黏性、终端需求弱 |

| **离线验证** | `mc_to_growth`：连续双宽 → 实体需求回暖 | 触发＝首次连续 3 期双宽、episode 去重；验证只用未来已发布数据，评估项见 §1.15 | **分层 1–3 / 3–6 / 6–12 月** | 参考级；命中率**待 M1 回测**，须带基准、显著性与样本外 | 信用派生扰动、政府债 / 化债冲量、输入性 PPI 上行、地产链拖累、GDP 修订 |

> **离线有效性评估（只读，衔接 §1.4 / §1.12）**：该信号只用于离线复盘与回测，验证「货币信用领先性」假设，输出 `signal_efficacy` 报告，不写回 `MacroSignal`。
> - **前视隔离**：t 时刻信号只用当时已发布数据，t+1..k 的验证值取已发布值 + `vintage` 快照；未来数据禁止回流在线 `factors` / `regime` / `phase` / `asset_alloc` / `equity_weight`。在线判定与离线评估分属不同作业与只读视图。
> - **分层窗口**：1–3 月看 PMI 新订单 / 生产、M1−M2 剪刀差、企业中长贷；3–6 月看工业利润同比与利润率、信贷脉冲、产成品库存；6–12 月 GDP 仅事后锚定（§1.3.0）。PPI 受油价与供给侧冲击同样可推高，不得作为「信号有效」判据。
> - **判定口径**：双宽多出现在衰退末段，PMI 低位反弹的无条件命中率本就高，且存在央行因弱宽松的反向因果。须用条件命中率 vs 无条件基准 / matched control + 事件研究累计异常，窗口重叠用 Newey-West 或 block bootstrap + 样本外滚动 + 仓位增量收益联合判定；报告须给出 episode 数、窗口重叠与置信区间，禁止用单点成功率充当命中率。
> - **测试断言**：T-5 未来数据不写回 `macro_signal`；T-6 命中率须带基准与显著性、样本外通过；T-7 失效条件触发降级为参考级。

#### 1.15.2 输出契约与落库

预测信号落 `signal.macro_forecast`，字段为 signal_id、chain、basis_period、lead_window、direction、confidence、hit_rate_status、invalid_if、as_of。

`MacroSignal` 的只读字段 `forecast_signals`（§1.7 JSON）供展示层一次性拉取，只读派生数据，不设任何指向 `macro_signal` 的回写路径。

#### 1.15.3 测试要求（挂 §1.11）
- 同一 `as_of` 下，任意改写 `macro_forecast` 内容，`macro_signal` 全部周期字段**逐字段全等**（隔离反例）。
- 预测信号构造时使用未发布期数据 → 抛错；预测输出不得改写当期 CPI / PPI 读数。
- `hit_rate_status='pending'` 时页面输出「待回测」，出现任何数值即判失败。
- 辅助 / 预测列表缺数据 → 空态 + 数据时间，出现 0 值或示例值即判失败。

### 1.17 宏观因子评分（对基准仓位的有界微调）

> **定位**：宏观层仍以 §1.3 状态机 + §1.4 查表定**周期象限与基准仓位中枢** `equity_weight_base`；在此之上叠加**宏观因子评分**，仅对基准仓位做**有界微调**得到最终 `equity_weight`。因子评分**不改变** `regime` / `money_credit` / `phase` 象限判定，也**不做**证券横截面排序。

**① 评分输入**

沿用 §1.2 四因子组（增长 / 通胀 / 货币 / 信用）在当期「最新已发布期」的标准化得分 `s_i ∈ [-1, +1]`（正 = 该因子对权益偏多，负 = 偏空）。

某因子组缺失或未发布时取 `s_i = 0`（中性）并打 `stale` 标记，**禁止插值兜底**（与 C-6 / §1.2 时效规则一致）。

**② 合成分**

`macro_factor_score = Σ w_i · s_i ∈ [-1, +1]`，`Σ w_i = 1`，`w_i ≥ 0`；权重 `w_i` 为**可配参数**（默认四组等权，单组权重上限 40%，防单因子主导）。

**③ 微调作用点（唯一）**

`equity_weight = clamp( equity_weight_base × (1 + κ · macro_factor_score), 0, 1 )`

- `κ` 为微调带宽系数，可配，默认 `0.10`（相对调整上限 ±10%），硬上限 `0.20`。
- 仅微调 `equity_weight`；`asset_alloc` 其余四项按 `equity_weight` 变化**等比吸收**，保持五项和 = 1 且 `asset_alloc.stock == equity_weight`，四项不单独评分。
- `style_tilt` 由 §1.5 状态映射决定，**不参与**本微调（避免风格与仓位双重放大）。

**④ 硬约束**

- 仍受 §1.4 查表区间与 C-5 约束：`equity_weight ∈ [0, 1]`，下游暴露不超过它；极端态（如滞胀 + 双紧）微调后不得高于该态查表上限。
- **可开关**：`macro_factor_enabled`（默认 `true`）；关闭或评分输入全 `stale` 时，`equity_weight = equity_weight_base`，退化为纯查表。
- **可审计**：信号库记录 `macro_factor_score`、各 `s_i` / `w_i` / `κ`、`equity_weight_base` 与最终 `equity_weight`；不写入对外语义的象限字段。
- **禁止未来函数**：只用最新已发布期（C-6）。

**⑤ 与横截面因子的区别**

本节是**规则化打分 + 线性合成 + 有界微调**，**不含**横截面 IC、分层、正交化、机器学习——那些只在中观排行业、微观排个股使用（§4.1）。宏观因子的时序验证另立 §1.18，只裁定取舍与权重，**不参与当期打分**。

`w_i`、`κ` 的默认值均为待验值，须经 §1.18 考卷 C 定档后方算固化。

**⑥ 测试断言**

- `macro_factor_score ∈ [-1, +1]`；单组 `w_i ≤ 0.40`。
- 微调后 `equity_weight` 恒落在 `equity_weight_base × (1 ± κ)` 带内并 `clamp ∈ [0, 1]`。
- `macro_factor_enabled=false` 时 `equity_weight == equity_weight_base`（逐格回归）。
- 象限反例：任意评分下 `regime` / `money_credit` / `phase` 与纯查表结果完全一致。

### 1.18 宏观因子回测（时序口径 · 四道闸门）

> **为什么单列**：宏观是月频、小样本、时序决策，直接套微观的截面 IC 与分层回测会批量产出假显著——2010 年以来不足 200 个月，二十个候选里最大 IC 的期望就有 0.16 上下——看着像信号，其实全是噪声。宏观回测因此单独定口径、单独定闸门，结论只裁定「留 / 删 / 定权」，**不用于当期择时**。
> **裁定对象有三件**：① 单个因子该不该留在 §1.2；② `money_credit` 九态与 `regime` 四象限的划分、36 格配额是否成立；③ §1.17 的权重 `w_i` 与带宽 `κ` 取多少。三者分开回测，结论不互相回灌。

#### 1.18.1 三张考卷

| 考卷 | 对象 | 方法 | 主判据 |
| --- | --- | --- | --- |
| A 因子有效性 | §1.2 四组候选指标（约 20 项） | 时序 IC（因子值 vs 未来 N 月指数收益）、Newey-West | `abs(IC)`、t 值、bootstrap 区间 |
| B 状态与配额 | 九态 × 四象限 × 36 格 | Episode 事件研究 + 分状态收益归因 | 命中率、episode 数、配额单调性 |
| C 组合层 | 最终 `equity_weight` 时序 | 逐月调仓回测 vs 三条基准 | Calmar、最大回撤、换手 |

考卷 C 是**唯一能证明「宏观有用」的考卷**：A、B 只回答单个零件灵不灵，C 回答装起来赚不赚钱。

#### 1.18.2 目标、对齐与基准

| 项 | 口径 |
| --- | --- |
| 主目标 | 沪深300 全收益（含分红再投）月频；辅：中证500、偏股混合基金指数——后者防「跑赢指数却跑输同行」 |
| 对齐 | 因子取 T 月末**已发布**值，收益取 T+1～T+N；T 为当月最后交易日。严禁用 T 月内后续发布的数据，违者按未来函数处理（C-6） |
| 前向窗口 | N ∈ {1, 3, 6} 月。N=1 为主判（宏观按月度调仓），N=3 看持续性，N=6 检验是否仅吃趋势 |
| 基准 ①  | 沪深300 买入持有 |
| 基准 ②  | 固定 80% 权益 + 20% 货币，不做任何择时 |
| 基准 ③  | 纯查表 `equity_weight_base`，不加 §1.17 微调 |
| 成本 | 单边 5bp；换手按权重变动绝对值累加 |

基准 ③ 是分离变量的关键：状态机与因子微调各自贡献多少，全靠它切开。基准 ② 则回答另一个问题——择时到底有没有比「什么都不做」更强。

#### 1.18.3 小样本必须做的四件事

| # | 问题 | 处理 |
| --- | --- | --- |
| 1 | N 月前向收益重叠，t 值系统性虚高 | Newey-West 调整，`lag = N − 1` |
| 2 | 月频样本少，IC 标准误大（n≈190 时约 0.07） | 报 block bootstrap 95% 区间（块长 6 月、1000 次），**不看单点 t 值** |
| 3 | 候选因子多，必有一个显著 | Benjamini-Hochberg FDR 控制，`q = 0.10`；报「通过数 / 候选数」而非单个 p 值 |
| 4 | 阈值与窗口搜索导致过拟合 | walk-forward：滚动 60 月训练 / 12 月测试，样本外拼接；参数冻结后才读测试段 |

> **去趋势是前置条件**：社融存量、M2 这类强趋势序列与指数长期上行天然正相关，直接算 IC 会得到「永远显著」的假象。统一先做 12 月差分或 36 月滚动 z-score 再算 IC；水平值 IC 只作参考、不作判据。
> **IC 切点**：n≈190 时 IC 绝对值须达 0.15 才越过约两倍标准误。因此 G2 用「显著性 + 分类错误率」把关，不设「IC>0.05 即有效」这类截面口径的宽松线。

#### 1.18.4 四道闸门与三档处置

| 闸 | 条件 | 不满足时 |
| --- | --- | --- |
| G1 方向稳定 | 滚动 5 年切 5 段，IC 同号 ≥ 4 段 | 降为观察项 |
| G2 统计显著 | BH-FDR `q < 0.10`，且 bootstrap 区间不跨 0 | 降为观察项 |
| G3 增量 | 相对基准 ③：Calmar 提升 ≥ 0.10 或最大回撤改善 ≥ 3pct，且换手增幅 ≤ 50% | 只做预警与 `confidence`，不进 `s_i` |
| G4 独立 | 与已留因子在 12 月差分后 `abs(ρ) < 0.7` | 留信息量大者，另一个出表 |

处置分三档，不存在「差不多能用就先用」：

| 档 | 条件 | 落点 |
| --- | --- | --- |
| 入评分 | G1–G4 全过 | 进 §1.17 `s_i`；`w_i` 按时序 IC 均值与波动（时序 IR）定，不默认等权 |
| 入观察 | 仅过 G1 + G2 | 进 §1.15 预测信号观察通道，不进评分、不动仓位（高频预警通道随 D-30 后移） |
| 出表 | 其余 | 移出 §1.2，登记进 §1.12 假设 16 的出表台账 |

> **两段行情必单列**：2014–2015 杠杆牛与 2019–2021 结构牛都由流动性与产业逻辑驱动，状态机在这两段天然滞后。报告须单列其表现；若整体 Calmar 提升全靠其余区间、而这两段显著劣化，按「借来的 alpha」处理，不计入 G3。
> **回填禁令**：出表因子若日后要回归，须作为**新增因子组**重新走 G1–G4 并同步展开状态空间，不得在旧权重上悄悄加回。回测结论只改配置，不改历史信号；参数变更走版本化 + 留痕（AD-05），当期照冻结参数执行。

| 二级（L2） | 134 | 细化层（可选）：在选定一级内比较细分方向景气度，支撑行业内轮动 | 月 / 季频 | 月 / 季 |

> **依据**：A 股行业轮动基准为申万一级；景气数据多为月 / 季频公开数据，申万口径覆盖全、成分清晰，星耀 `get_industry_constituent` / `get_industry_daily` 同源无需跨源 JOIN。三级广度 / 流动性 / 换手均差，不宜直接轮动。

### 2.2.0 景气度的数据母体：从宏观数据拆到行业（含滞后补偿）

> **为什么这么拆**：宏观统计（统计局工业司、海关、央行、能源局）是**唯一覆盖全行业、口径统一、免费可得**的月度数据体系；行业级私有数据（协会、另类）只覆盖部分行业且口径不一。因此**以宏观分项为骨架、协会/另类为补丁**，是覆盖率最高的做法。

**① 宏观 → 行业拆解映射（四维各自的数据母体）**

| 中观四维 | 宏观母体指标（月频） | 拆解到行业的方法 | 行业粒度 | 发布时点（次月） |
| --- | --- | --- | --- | --- |
| **景气度** | 分行业**工业增加值**同比、工业企业营收/利润同比（按大类行业）、制造业 PMI 分项 | 统计局"规模以上工业分行业增加值"直接映射申万一级；营收/利润按行业大类汇总（星·基本逐股聚合校验） | **L1 可直接对应**；L2 需按收入结构加权拆分 | 增加值 ~15 日；利润 ~27 日 |
| **需求** | PMI 新订单/在手订单、分行业**固定资产投资**、社零分项 | PMI 为全制造业总量（**不分区**，只能作共性项）+ 固投/社零按行业分项映射 | L1 部分可分（固投/社零有分项）；L2 弱 | 固投 ~15 日；社零 ~15 日 |
| **出货量** | 分行业工业增加值（量）、主要工业品**产量**、**出口交货值 / 海关出口金额**（按 HS 编码，分地区 / 分商品明细见 §1.2.2） | 产量表（粗钢/水泥/十种有色/汽车/手机等）直接对应行业；海关 HS → 申万行业映射表 | L1 好（重点产品全）；L2 依赖 HS 映射 | 海关 ~7~13 日；产量 ~15~18 日 |
| **价格** | **PPI 分项**（生产资料/生活资料 + 细分行业出厂价）、CPI 分项（明细清单见 §1.2.2） | PPI 分项直接对应行业出厂价；CPI 分项对应消费行业终端价 | **L1 最好**（PPI 分项≈行业口径） | ~9~10 日 |

> **结论**：价格（PPI 分项）与出货量（产量 / 出口）拆解质量最高，可直接对齐申万一级；景气度次之；需求最弱（PMI 不分区、固投偏投资端），须由协会订单调查 + 另类数据补强（§2.2.1）。

**② 滞后结构（为什么中观是月频、且天然"慢半拍"）**

| 环节 | 时滞 | 说明 |
| --- | --- | --- |
| 统计期 → 发布 | **9~27 天** | PPI/CPI 最早（9~10 日）、进出口（7~13 日）、增加值/固投（15 日前后）、工业企业利润（27 日） |
| 发布 → 数据齐备 | **+5~10 天** | 四维全部到期须等最慢的利润数据，故**次月中旬（约次月 20~25 日）**才能形成完整月度快照 |
| 累计同比口径 | **+1 个月** | 统计局多用累计同比，单月值需自行差分，差分进一步放大噪声 |
| 策略取数 → 调仓 | **+1 个月** | 默认季频调仓可稀释此滞后；月频调仓则需接受"用 T-1.5 月信息做 T 月决策" |

> **量化表述**：中观信号的有效信息时点 ≈ **信号月结束后 30~45 天**。故中观对市场的**领先性不来自自身频率，而来自"景气趋势的持续性"**——景气周期通常持续 2~4 个季度，1.5 个月滞后不改变方向判断，但会**错过拐点初期的 1~2 个月**。

**③ 滞后补偿（把"慢半拍"补回来）**

| 手段 | 做法 | 补哪一维 | 频率 |
| --- | --- | --- | --- |
| **① 市场价格前移** | 用 PPI 高频代理（商品期货/生意社/南华指数）**日频**跟踪行业价格，领先 PPI 发布 3~6 周 | 价格 | 日频 |
| **② 协会/另类前移** | 中汽协销量、信通院出货、装机量等月度先行指标 + 高频开工率/库存 | 景气度、出货量、需求 | 周/月 |
| **③ 趋势外推** | 对已发布序列做**滚动环比动量**（3M/6M 年化），用趋势而非点位打分，降低单月滞后影响 | 全四维 | 月 |
| **④ 微观反哺（只预警不调仓）** | 日频行业 ETF 估值分位 + 拥挤度/资金流极端值，作为**中观两次调仓之间的预警**（§2.5 日频监控清单）；**完整机制见 §2.2.3** | 全部 | 日频 |
| **⑤ 宏观相位先行** | 宏观（§1）已用 PMI 等**更早发布**的数据定位周期相位（PMI 月末即出），中观行业排序在相位框架内做，避免行业信号独木难支 | 全部 | 月频 |

> **不得做的事**：微观日频信号**不得反向改写**中观四维打分（高频侵蚀低频会削弱中观独立信息）；微观只做预警与择时，方向由月频景气决定（§2.5）。

**④ 拆解口径的三个陷阱（须在实现层处理）**

1. **累计同比 vs 单月同比**：统计局多为累计口径，跨年 1~2 月合并发布（1-2 月合报），须统一转单月同比并做春节调整，否则每年 1~2 月出现假拐点。
2. **行业口径不一致**：统计局"大类行业"（41 个工业大类）≠ 申万一级（31 个），须建**映射表 + 权重拆分**，如"汽车制造业"拆分到申万汽车；"计算机通信电子"对应电子+通信。映射表为数据资产，与《申万一级行业 ETF 映射表》并列维护。
3. **基数效应**：2020 年后同比基数剧烈波动，须同时看**两年复合增速（CAGR2）**，单看同比会在低基数月虚高。

### 2.2 一级景气度打分（四维合成）

行业优先级由以下**四维**合成，**月/季频滚动计算**（数据频率月/季、调仓频率月/季，见 §2.5）。**行业池先经 §2.3 五年规划筛选**，池内再打分；估值**不进入本打分**，仅作低频硬约束与微观日频反哺（见下「估值双定位」）；具体权重与阈值在 M1 因子引擎验证后固化，当前为默认：

| 维度 | 数据（数据层 §2.2） | 语义 | 默认方向 |
| --- | --- | --- | --- |
| **景气度** | 行业协会景气指数/景气调查、行业 PMI、行业营收/利润增速、分析师景气预期 | **当前综合景气位置**（现状而非边际） | 位于扩张区间且高于中位数 → 加分 |
| **需求** | PMI 新订单/在手订单、行业订单景气调查、下游资本开支/产销率 | 下游需求强度（有没有订单） | 订单扩张 → 加分 |
| **出货量** | 分行业工业增加值、产量同比、出口交货值/海关出口量、销量 | 实物量产销规模（有没有真出货） | 量增 → 加分 |
| **价格** | PPI 分项、行业出厂价、商品价格指数（生意社/南华） | 价格水平与趋势（卖得贵不贵） | 价升（非过热）→ 加分 |

> 四维的宏观母体见 §2.2.0 ①，此处不重复。

> **辅助观察项（不单独成维、不计入权重）**：应用规模（渗透率 / 装机量 / 用户规模）仅作结构性备注，数据可得性最差（§5），M1 验证增量 IC 显著后再升级为第五维；景气动量由四维同比 / 环比边际变化派生，作时序平滑项（默认 ±0.25 档）；政策契合度不作打分维度，已上升为行业池准入（§2.3）。
> **估值双定位（不进入四维打分）**：① **低频硬约束**——季度层面做泡沫对冲，行业 PE / PB 分位 > 阈值（默认 90%~95%）即降权 / 剔除，不参与横截面打分；② **短期观察**——两次决策之间消费微观（§3.1.1）的日频行业 ETF 估值分位做过热预警，只预警不调仓（§2.5）。

→ 输出 **行业景气度 Top-N**（默认 N=5~8）超配清单，作为微观层「行业 ETF 核心仓 + 行业内个股卫星仓」的行业取向（微观具体择时与选券见 §3）。

### 2.2.1 景气度三源融合与交叉验证

景气度每维应至少两类来源印证，避免单一源口径偏差、滞后、粉饰或停更导致误判。三类来源对景气维度的覆盖与组合规则如下：

| 数据源 | 代表信号 | 典型来源 | 角色 |
| --- | --- | --- | --- |
| ① 市场价格 | PPI 分项、商品价格指数（生意社/南华）、行业指数、期现价差 | akshare 宏观/商品、星耀 `get_industry_daily` | 最实时、最"诚实"的供求结果信号 |
| ② 行业协会报告 | 产销、订单、库存、景气调查：中汽协销量、中钢协粗钢、中电联发电、信通院手机出货、家电协会零售等 | 行业协会月/季报、行业研报 | 权威"实物量"口径，贴近真实产出 |
| ③ 另类数据 | 渗透率、装机容量、终端出货、用户规模、卫星/爬虫/供应链流水 | 第三方另类数据商、企业财报、爬虫 | 前瞻性强，补官方低频缺口 |

**组合判断规则**：
- **三源同向（均景气上行）→ 强确认**：上浮一档权重，可前瞻于财报布局。
- **两源同向、一源背离 → 分歧**：降权/观望，优先采信"市场价格"（最诚实），再用协会报告核验方向。
- **市场价格已反映、另类/协会未跟上 → 趋势确认但防预期透支**：配合微观行业 ETF 拥挤度（§3.1.1）控回撤。
- **单一来源缺失/停更 → 不致命**：另两类仍可组合判断（多源架构核心价值，见数据层 §2.2 / §5）。

> 四维与三源映射：**景气度**→②协会景气调查 + ①行业指数 + ③营收增速；**价格**→①市场价格；**出货量**→②协会报告 + ③另类（终端出货）；**需求**→②协会订单调查 + ③另类（消费流水）。每一维尽量 ≥2 源印证；政策契合度不属景气驱动，已上升为行业池准入（§2.3），应用规模与景气动量为辅助项（§2.2）。

### 2.2.3 高频辅助：微观反哺中观（Micro → Meso Nowcast）

> 中观四维是月 / 季频，行业指数、行业 ETF 价格 / 估值 / 份额、成分股资金流是日频；景气拐点通常先在价格与资金上体现，2~4 周后才在统计局数据上确认。本节定义这些日频信号如何反哺中观。

#### 2.2.3.0 中观辅助与校正组（归微观、不打中观分）

> 中观四维是**基本面**判断（生意好不好），估值 / 资金流 / 拥挤度 / 杠杆率是**价格与仓位行为**判断（贵不贵、挤不挤、加没加杠杆）。四项一律在微观计分（§3.1.4 / §3.1.6 / §3.1.2 / §3.1.8），中观只读方向。

> **「校正」的边界**：校正的是 `meso_confidence`、风险姿态与预警等级，最极端只到「当期不新增」。**四维分值 `meso_score` 一分不动**——四维答「生意好不好」，这四项答「现在买贵不贵」，混在一个分里会让中观失去独立信息（回测低估四维 alpha、实盘把已被炒高的行业推更高）。
> **硬约束**：四项不得作为第五维、不得进四维加权、不得因高拥挤下调景气分、不得单独决定减仓。
> **三条铁律**：① 高频只调姿态与置信度，不改四维打分；② 只预警不调仓（预警排队到下次调仓窗口）；③ 同一指标只进一处（估值 / 拥挤度在微观计分，中观只读方向）。

#### 2.2.3.1 反哺指标清单（哪些微观日频信号可以"喂回"中观）

| 反哺信号 | 频率 | 印证中观哪一维 | 方向解读 | 数据层 |
| --- | --- | --- | --- | --- |
| **行业指数/行业 ETF 相对强弱（20/60 日超额）** | 日 | **景气度（综合）** | 行业跑赢全市场 = 市场在**提前定价景气改善**；持续 20 日超额 + 行业基本面未变差 → 强印证 | §3.1.9 ETF 行情 / 星·`get_industry_daily` |
| **行业 ETF 日频估值分位（PE/PB 滚动分位）** | 日 | **价格 + 景气度** | 估值分位抬升常伴随景气预期上修；但分位过高（>90%）反而是**透支信号**，反转用途 | §3.1.9 |
| **行业 ETF 份额变化（净申购）** | 日 | **需求** | 份额持续净增 = 场外资金在申购该行业，是需求侧的前瞻代理 | §3.1.9 |
| **行业 ETF 溢价率** | 日 | **需求（情绪）** | 持续溢价 = 抢筹；持续折价 = 抛压。**仅作方向盘，不作打分** | §3.1.9 |
| **成分股主力净流聚合（行业口径）** | 日 | **资金面（非景气）** | ⚠️ **不反哺景气**——资金流是交易行为，属微观；仅作预警（流入极端 = 可能要启动，流出极端 = 可能已在派发） | §3.1.9 |
| **行业拥挤度综合分位** | 日 | **风险（非景气）** | 高拥挤 = 即便景气好也可能踩踏，触发中观"降权预告" | §3.1.1.1 |
| **行业杠杆率（融资余额÷流通市值、融资净买入÷成交额）** | 日 | **风险（非景气）** | ⚠️ 不反哺景气：杠杆属资金行为；杠杆升而景气未改善 = 情绪透支，触发降权预告；同降 = 双出清（§3.1.2） | §3.1.9 |

> **必须区分两类反哺**：**景气类**（相对强弱、估值、份额）可以"印证景气"，**交易类**（**资金流、拥挤度、杠杆率**）只能"提示风险"。**交易类永远不得被解读为景气变好**——这是中观与微观分层的底线。四项的完整定位与使用边界见 **§2.2.3.0**。

#### 2.2.3.2 反哺的三种用法（由弱到强，都不改打分）

| 用法 | 触发条件 | 动作 | 是否改调仓 |
| --- | --- | --- | --- |
| **① 置信度修正** | 微观日频方向与中观四维方向**一致** | 该行业 `meso_confidence` 上调一档（低→中→高），可用于**同分排序时优先** | 否（只在同分时排序） |
| **② 预警排队** | 微观与中观**背离**，如中观景气上行但行业 ETF 连续 20 日跑输 + 估值分位跌破 30% | 标记 `meso_nowcast_divergence`，**排入下次调仓窗口优先审议**；当期不动 | 否（排队，不等价调仓） |
| **③ 极端风险拦截** | 拥挤度 > 95% 分位（§3.1.1.1）或行业 ETF 单日跌幅 > 7% | **当期不新增该行业**（新增被拦），已持有按微观规则减仓 | **是**（仅"不新增"与"按微观减"，非中观调仓） |

> **用法③是唯一允许"影响实际操作"的路径，且它不是中观调仓**：中观的超配清单不变，只是微观在执行时按自身风控拒绝新增。这样既保住中观独立性，又不会在极端拥挤时机械买入。

#### 2.2.3.3 与宏观高频层的结构对齐

| 维度 | 宏观高频辅助（D-30 后移） | 中观 §2.2.3（D-25 暂缓） |
| --- | --- | --- |
| 快通道（可改动仓位） | 外生突变 → `delta_pct`（含危机强制下限） | 拥挤度极端 → **仅拦截新增**（不调清单） |
| 慢通道（只改置信度） | 内生高频印证 → `confidence_delta` | 相对强弱/估值/份额 → `meso_confidence_delta` |
| 铁律 | 不改 `regime` | **不改四维打分** |
| 指标去重 | 同一指标只进一处（美元/中美利差 vs 10Y/信用利差） | 估值/拥挤度在微观计分，中观只读方向 |

#### 2.2.3.4 输出与契约

```json
{
  "industry": "SW_801080",
  "meso_score": 0.62,
  "meso_confidence": "中",
  "meso_nowcast": {
    "hf_state": "confirm | divergence | risk_block",
    "signals": { "excess_20d": 0.043, "pe_pctile": 0.68, "share_chg_5d": 0.012, "crowding_pctile": 0.91 },
    "warn_flags": ["meso_nowcast_divergence"],
    "block_new_entry": false
  }

```

**契约约束**：`meso_nowcast` **不得回写** `meso_score`（四维打分结果）；`block_new_entry=true` 只拦截**新增买入**，不修改中观超配清单与权重（§2.6）。

### 2.3 五年规划行业池（行业准入 · 先验约束）

> **定位升级**：五年规划不再是"景气打分的一个加分项"，而是**行业池的准入条件**——先圈定"国家要发展的行业"，再在池内做四维景气打分。这样既保证组合不偏离国家产业方向，也避免"政策加分"与"景气打分"对同一逻辑双重计量。

**① 行业池构建（先验）**

1. **取词**：从最新五年规划纲要、战略性新兴产业目录、政府工作报告及相关专项规划中提取产业关键词，如集成电路、工业母机、人工智能、新能源、生物制造、商业航天、低空经济、新材料等。
2. **映射**：关键词 → 申万一级/二级行业，形成 `policy_pool`（重点池）与 `policy_watch`（观察池，政策提及但非重点）。
3. **更新频率**：半年/年（规划发布或重大政策调整时），不参与日内。

**② 池的三层结构与准入规则**

| 层 | 定义 | 准入 | 配置权重 |
| --- | --- | --- | --- |
| **主池 `policy_pool`** | 五年规划明确重点支持的行业 | 申万一级落在重点清单 | 可超配，权重上限不受限 |
| **观察池 `policy_watch`** | 政策提及但非重点 / 新兴未定型 | 四维景气 ≥ 2 维强正向时才可入选 | 单行业权重 ≤ 主池行业的一半 |
| **池外** | 政策未提及/受限行业（高耗能、落后产能等） | 不纳入中观打分 | 默认不配；确需配置须标注理由并留痕 |

**③ 与景气度打分的关系**

- **先池后分**：先在 `policy_pool` / `policy_watch` 内圈定集合，再按 §2.2 四维排序产出 Top-N。
- **政策与景气共振**：主池 + 四维全正向 = 强超配；主池但景气下行 = 仅观察、不硬配（政策不替代景气）。
- **池动态调整**：政策退坡 / 受限即移出至池外；新政策出台则新增关键词并重映射，留版本记录。
- **数据来源**：政策文本 / 公告 / 研报，来源【星·公告】TAG 与【mx-finance-search】；NLP 词表匹配 + 人工复核。

### 2.4 宏观 → 中观衔接（风格白名单）

中观层在合成打分前，**先套用宏观 `style_tilt` 白名单**（定义见 §1.5）：

| 宏观 regime | 中观行业加权偏好 |
| --- | --- |
| 复苏 | 周期/金融/成长 加权，防御降权 |
| 过热 | 周期/资源/价值 加权 |
| 滞胀 | 消费/公用事业/医药（防御）加权，周期/券商降权 |
| 衰退 | 科技/医药（利率敏感/成长）加权 |

总暴露上限 = 宏观 `equity_weight`（硬约束，见 §1.7/§1.8）。超配行业清单内权重在景气度打分下分配，合计 ≤ `equity_weight`。

### 2.5 频率与双维轮动（低频基本面节奏）

**频率：数据月/季频、调仓月/季频**

| 维度 | 频率 | 说明 |
| --- | --- | --- |
| 数据 / 分析 | **月 / 季频** | 三源统一取月 / 季频快照：价格取月均、协会取发布值、另类取最新可得；政策半年 / 年更新；拆解类信息次月中旬齐备（§2.2.0 ②） |
| 调仓 / 操作 | **月 / 季频**（默认季频，可配置） | 仅在景气度打分刷新后调整行业超配，避免低频信号被高频噪声干扰 |

> 与微观边界：中观不盯盘、不做日内 / 周度择时，产出「超配哪些行业」；微观决定「何时、以什么信号交易」。日频监控只预警并排队到下次调仓窗口，监控项为估值过热、资金流与拥挤度极端、ETF 相对强弱背离；唯一例外是拥挤度 >95% 分位或行业 ETF 单日跌幅 >7% 时拦截新增（§2.2.3.2）。

**双维度轮动（行业取向层面）**

```
景气度刷新(月/季) ──► 行业池内依据四维打分（估值仅作低频硬约束/预警，不参与）：
   ├─ 跨行业轮动：一级行业 Top-N 进出 → 超配行业清单更新（换赛道）
   └─ 行业内轮动：持有行业内细分方向比较 → 二级景气度强弱切换（换马）
        └─ 二级景气度强弱 → 交微观在该行业内选 ETF/个股
```

| 轮动维度 | 触发条件 | 产出 | 责任层 |
| --- | --- | --- | --- |
| 跨行业 | 景气度 Top-N 进出 / 行业池调整 | 超配行业清单 | 中观 |
| 行业内·二级 | 持有行业内二级景气度反转 | 细分方向优先级 | 中观 |
| 行业内·个股/ETF | 微观在选定行业内做日频六维精选 | ETF 主仓 + 个股卫星 | 微观 |

### 2.6 中观 → 微观衔接（产出消费）

中观层合成打分后，向下游输出**行业超配清单**（行业取向约束）；估值不在此层传递（见 §2.2「估值双定位」）：

| 中观产出 | 微观消费 |
| --- | --- |
| 超配行业清单（Top-N）+ 权重倾向 | 微观在清单内优先选对应**行业 ETF（核心仓）**与**行业内个股（卫星仓）**；清单外行业 ETF/个股降权或剔除 |
| 估值低频硬约束结果（极端高估行业已降权/剔除） | 微观在清单内不再碰已被中观剔除的高估行业 |
| 行业池（五年规划） | 重点支持行业在微观 ETF/个股选择中保留结构性偏好 |

> 具体的行业 ETF 选择（规模/成交额/溢价率/份额变化/资金流/拥挤度/两融杠杆）与个股六维精选，由微观（§3）在日频上执行——这些**交易行为信号属微观，不出现在中观**。

### 3.0 微观优先模式 micro_first（D-25 · 本期默认）

> **本节是微观优先模式的唯一权威**：运行形态、universe、输入 / 输出契约、宏观隔离铁律、软约束与数据消费口径。需求拆解见《需求文档》§5.4（MI-01~MI-08）与 §5.9（AD-12 / P11），工程承载见《系统设计总文档》§3.7。

> **数据需求口径（D-25）**：微观层数据母体为「全市场 A 股 + 已映射行业 ETF」，六维数据需求与来源以 §3.1.4–§3.1.9 / §3.1.3 为唯一出处，**不新增、不改名、不重排**；中观数据需求（§2.2.2）本期不采集、不落库、不展示空表。

**① 运行形态**

```
采数(Python CLI) ──┬─► 宏观引擎(月频·§1) ──► macro_signal / asset_alloc（零改动）
                  └─► job-universe(日/周频·§3.0②) ──► 准入名单 universe_scope
                                      └─► 微观引擎(日/周频·§3.1) ──► MicroSignal 批次 ──► #micro 只读展示

```

**② 候选域 universe（三模式，本节为唯一权威）**

- **覆盖范围**：候选域由下列三模式确定（本期默认 `industry_first`）；行业分类以申万一级为唯一基准（C-8，禁止东财 JOIN），个股与 ETF 为**同级标的**，同一套六维、同一批次。
- **准入过滤（前置、非宏观配置）**：ST / 退市 / 停牌 / 新股 / 流动性不足一票否决（与 R-RK-1 同源），过滤后 universe 数量写入批次摘要；无 ETF 映射的行业标「待补」，不阻断其余标的。
- **不依赖**：中观 Top-N 行业清单、五年规划行业池、行业取向、`style_tilt` 白名单。中观缺位不得被解释为「无行业可投」或「等权全行业」。

| 模式 | 候选域 | 评分顺序 | 行业 ETF | 适用 |
| --- | --- | --- | --- | --- |
| `industry_first`<br>**（本期默认）** | 申万一级行业六维聚合 **Top-N**（默认 5）准入行业内的个股 + 对应行业 ETF | 行业截面聚合 → 准入名单 → 准入域内个股 / ETF 六维 | 跟随准入行业名单 | 本期生产默认 |
| `index_constituent` | 指定指数成分，可选中证 500、中证 1000、沪深 300、中证全指等 | 按 `as_of` 取当期生效成分域 → 域内六维 | **ETF 不属指数成分**，按配置排除或单独保留 | 用户指定；可与行业准入名单取交集 |
| `full_market` | 全部 A 股 + 已映射行业 ETF | 直接六维 | 全部 | **仅对照 / 消融测试**，不作生产默认 |

**行业六维聚合口径**：行业分 = 该申万一级行业内成分股六维分的**截面聚合**（市值加权 / 等权可配、改参留痕），按行业横截面标准化后取 Top-N 形成**准入名单**。**申万一级为唯一行业基准，禁止东财 JOIN**；行业 ETF 沿用《申万一级行业 ETF 映射表》。

**范畴隔离（硬断言）**：行业评分是**六维因子的行业截面聚合**（微观方法上移），**不是**中观四维景气度模型（§2 继续 ⏸ 暂缓）；**只产出准入名单，不产出行业超配比例 / 配置权重 / 建议金额**，不写回 `macro_signal`、不改 `confidence`、不触发调仓。M2-R 中观重启时由中观接管行业评分，六维聚合降级为交叉校验或废弃，**禁止两套行业评价并存**。

**数据与时点**：指数成分映射须带 **PIT 生效日**，按 `as_of` 取当期生效成分，**禁止前视**；新增数据项与引用登记见 §4.5 `dataRefs`。准入过滤（ST / 退市 / 停牌 / 新股 / 流动性不足）仍在域构建后前置执行，与 R-RK-1 同源，**不属**宏观资产配置。

**风险登记（量化）**：个股六维分聚合为行业分、再在行业内选个股，存在**同一因子双重使用 / 选择偏差**；行业聚合分高**不等于**行业内个股优。行业层与个股层须使用**不同截面的标准化口径**（行业层用聚合后横截面，个股层用原始截面），并以 M1 的 IC/IR 与样本外分层验证；**未通过前行业名单只作软约束，不得固化成结论或配置**。

**行业选择为主区 · 标准综合评分 + 原始数据 / 评分双列明细**：本节为**行业评分口径的唯一权威**，《需求文档》MI-11 / MI-12 只写功能与验收。

**① 标准综合评分公式（排序唯一依据）**：每个原始观测值先在申万一级 31 行业截面上 winsorize（1% / 99%）→ z-score 标准化（或分位映射 0–100，二选一全站一致、改参留痕）得 `dim_score`；`composite_score = Σ(dim_score_i × w_i)`，默认 `w = 20 / 12 / 20 / 18 / 15 / 15`（Σ=100%）。行业榜按 `composite_score` 降序。严禁用 PB / PE / PS 原始值直接跨行业排序（银行 PB 0.5 与半导体 4.3 不可比）。

**② 原始观测值口径（解释层）**：六维原始值定义见 §3.1.4–§3.1.9。行业估值一律**整体法**（合计口径，非成分股简单平均）、**负 PE 剔除或单列**；每项明细同时给出**原始值、该项标准评分、近 5 年历史分位、行业中位数**——评分用于排序、原始值用于解释。

**③ IndustrySignal 输出契约（独立，不污染 MicroSignal）**：`industry`（申万一级代码 / 名称）、`composite_score`、`rank`、`dims[]{raw_values, dim_score, percentile_5y, median_cross}`、`crowding`、`leverage`、`margin_balance`、`index_trend_10d[]`（近 10 个交易日行业指数收盘序列 + 区间涨跌幅）、`admitted`、`as_of`。**字段白名单**：不含 `weight` / 目标占比 / 建议金额 / 组合权重 / 行业超配比例 / 任何宏观配置字段；`MicroSignal` 白名单（§3.1）保持不变。

**④ 展示筛选 ≠ 信号计算（硬断言）**：页面按综合评分 / 拥挤度 / 杠杆率 / 融资余额的筛选**只过滤展示行**，**不得回写或改变**准入名单、`universe_scope` 与 `IndustrySignal` 批次内容；综合评分 Top-5 默认展开、其余点击展开亦**仅为交互**，不参与计算。

**⑤ 因子归位**：六维**因子定义、权重、有效性与回溯校验**的唯一展示位为管理端 `#strategy`；`#micro` 明细表**不渲染权重列**，仅展示原始值与分项标准评分。

**⑥ 时点与缺失**：估值 / 财务 / 成分 / 指数收盘一律 PIT（按 `as_of` 取当期可得，**禁止前视**）；10 日走势交易日 ≤ `as_of`；缺失展示空态，**不填零、不补前值、不覆盖原值**。行业层与个股层须使用**不同截面的标准化口径**，不得把行业 `dim_score` 直接当作个股六维分使用（缓解 D-26 因子双重使用 / 选择偏差）。

**③ 输入契约**：候选域三模式 + 行业六维聚合参数 + 指数成分 PIT 映射 + 准入过滤清单（本节 ② / 映射表）；六维因子原始数据（§3.1.4–§3.1.9）；因子评估与合成参数（§3.2）；行业集中度 / 分散度参数（本节 ⑤）。

**禁止输入（硬断言）**：`style_tilt` / `equity_weight` / `asset_alloc` / 中观四维景气度打分 / meso Top-N 行业清单 / 五年规划行业池 / 未生效的指数成分批次。任一出现即任务终止并留痕（反例测试）。

**④ 输出契约 MicroSignal**

| 字段 | 类型 | 约束 / 口径 |
| --- | --- | --- |
| batch_id / as_of / point_in_time | str | 批次、数据时点与取数时点；同输入同输出可复现 |

#### 3.1.1.1 拥挤度细化（「有多少资金在这个行业里」）

> **定义（用户口径）**：拥挤度＝**有多少资金在这个行业里面**。因此拥挤度不是单一指标，而是「**存量资金占比 + 资金行为强度 + 由此得到的综合分位**」三组子项合成；其中**存量占比是主口径**（回答"人多不多"），换手/筹码/溢价是**行为与结构证据**（回答"人还在不在、是不是同一批人"）。

**① 三个子口径**

| 子口径 | 指标 | 分子 / 分母 | 语义（回答什么） | 数据来源 |
| --- | --- | --- | --- | --- |
| **存量占比（主口径·计分）** | **集中度倍数**（行业成交占比 ÷ 行业市值占比）+ **换手率** | （行业成交额 ÷ 全 A 成交额）÷（行业流通市值 ÷ 全 A 流通市值） | **钱在这个行业里的密度**——被交易得比其体量应有的更热多少倍，且不受价格水平变动污染 | 【星·SDK】`get_industry_daily` `AMOUNT`/`A_FLOAT_CAP`（行业与全 A 同表） |
| 存量占比（**参考·不计分**） | 融资余额 ÷ 流通市值 | 行业融资余额 ÷ 流通市值 | "有多少资金是**杠杆**资金、占市值多重"（计分在杠杆率维 §3.1.2） | 融资余额【星·SDK】`get_margin_detail`（`is_local=False`）；流通市值【星·SDK】`get_industry_daily` `A_FLOAT_CAP` |
| 结构基准（分母，不计分） | 行业流通市值 ÷ 全 A 流通市值 | 行业流通市值 ÷ 全 A 流通市值 | **结构基准**：该行业体量本来占多少，用于把成交占比折算成"超出常态"的倍数 | 【星·SDK】`get_industry_daily` `A_FLOAT_CAP` |
| **行为强度（证据）** | 换手率、净流连续天数、筹码集中度/筹码峰、ETF 份额变化、ETF 溢价率 | — | 资金是**在进还是在出**、是否已形成单一持仓峰（易踩踏）、ETF 是否被溢价抢购 | 换手【星·SDK】`query_kline`；筹码【westock】`chip`；ETF 份额/溢价【星·etf_dca】/【westock】`etf` |
| **综合结果（打分口径）** | **拥挤度综合分位**（0–100%） | 由上述指标**截面 Z 分位 → 等权/IC 加权合成 → 滚动分位** | 最终输出给六维评分与阈值触发（§3.1.1.2 聚合规则） | 派生计算 |

> **相对基准**：成交占比必须转成「**成交占比 ÷ 市值占比**」的**集中度倍数**再评分——倍数 > 1 表示该行业被交易得比其体量应有的更热，避免大盘行业天然成交额大而被误判拥挤；**自由流通市值占比仅作分母基准，不进打分**。
> **两处"存量占比"的分工**：拥挤度侧用「成交/换手的**资金密度**」回答"钱在这里多不多"；杠杆率侧用「融资余额/流通市值」回答"杠杆堆得高不高"。前者是**全资金**口径、后者是**杠杆资金**口径，语义不同但共源（融资余额也在成交里），故按上文去重规则执行。

**② 拥挤度分位合成与阈值（对应 §6.2 E3）**

```
存量主口径（计入打分）: 成交占比 ÷ 市值占比（集中度倍数）+ 换手率 + 筹码集中度（含筹码峰形态）
      参考（不计分，仅方向引用）: 融资余额/流通市值  ← 该比率在「杠杆率」维（§3.1.2）计分，防同一数据扣两次
      辅助（ETF 侧）: ETF 份额变化 + 溢价率
拥挤度综合分位 = mean_pctile(上述计分项)   ← 通用形式；若 M1 验证 VIF ≤ 5 可改回全项等权
     ├─ 单指标滚动 95% 分位 → 单点拥挤信号（预警）
     └─ 多指标共振（≥3 项同时 >95% 分位）→ 高拥挤 → 强制减仓 / 退出
```

| 综合分位 | 状态 | 处理 |
| --- | --- | --- |
| < 50% | 冷清/正常 | 不干预；低位 + 资金开始流入 = **潜在启动**（景气度支持时可加仓） |
| 50%~85% | 升温 | 正常持有，权重不再上调 |
| 85%~95% | 拥挤预警 | 降权一档；不再新增买入；预排队下次调仓窗口（§2.5 日频监控清单） |
| > 95% 或多指标共振 | **高拥挤** | 强制减仓/退出（E3）；若同时景气度仍上行 = "强 alpha 但高踩踏风险"，优先兑现 |

> **与杠杆率维的边界（去重规则）**：`融资余额/流通市值` 是拥挤度与杠杆率的**天然共用数据**——拥挤度关心"钱多不多"，杠杆率关心"杠杆堆得高不高、在加还是在减"。**该比率只在杠杆率维计分**（§3.1.2），拥挤度侧保留**方向引用**（融资余额在增 = 钱在进）但**不计分**，实际计分改用「集中度倍数 + 换手 + 筹码（含筹码峰）」。两维相关性由 M1 做 VIF 检验（§6.2 E6），**VIF > 5 则合并为「拥挤-杠杆率」单维**——**VIF 检验为必要防线**。
> **筹码峰归属**：筹码集中度（`conc90` / `conc70`）与筹码峰形态为**拥挤度行为维的子项**，不再单列维度；「筹码峰」在策略页权重表中已并入拥挤度一行。

#### 3.1.2 杠杆率细化（两融双比率 · 六维之⑥ · 行业 ETF 与个股共用）

> **杠杆率维定位**：本节为独立维度「**杠杆率**」（六维之⑥）。拆解逻辑、四象限判定、分母坍塌处理**全部保留不变**，占用独立评分权重（默认 15%，见上）。
> 行业 ETF 的两融指标来自其申万成分股聚合，与个股两融同源。以下拆解逻辑同时服务 ETF 与个股。
**口径硬约束（用户定义）**

两融子项由**两个比率**构成，缺一不可——**

- ① 融资余额 ÷ 流通市值**（存量杠杆：资金在市值的占比有多重）；**
- ② 融资买入额 ÷ 成交额**（流量杠杆：今天的成交量里有多少是杠杆资金打的）。前者看「杠杆水位」，后者看「杠杆火力」；**单看任一个都会被误判**，存量高但今日无买入 = 死仓不构成边际压力；存量低但今日买入额占成交 20% = 正在快速加杠杆，故必须**搭配四象限联合判定**（见第 3 层）。

> **第 1 层｜两个比率的分工（先明确各看什么，再谈搭配）**

| 比率 | 计算 | 类型 | 看什么 | 单看时的缺陷 |
| --- | --- | --- | --- | --- |
| **比率 A：融资余额 ÷ 流通市值** | 存量 ÷ 存量 | **存量杠杆（水位）** | 杠杆资金已占市值的比重＝杠杆"堆了多高" | 分母含价格，**价跌会被动推高比率**（分母坍塌伪信号）；且对"今天在不在加杠杆"无反应 |
| **比率 B：融资买入额 ÷ 成交额** | 流量 ÷ 流量 | **流量杠杆（火力）** | 今日成交中有多少由融资买入构成＝杠杆资金"此刻的参与度" | 是**快变量**、噪声大、易被单日撬动；无法说明杠杆存量是否已过高 |

> 两个比率是**存量与流量、慢与快**的关系：A 回答"杠杆资金在这个行业里占多重的仓位"，B 回答"杠杆资金今天有多用力"。A 高 B 低 = 杠杆盘套牢/趴着不动（存量压力大但无边际买盘）；A 低 B 高 = 杠杆刚开始进场（存量不大但加速中）。**必须搭配看**，判定见第 3 层四象限。

**第 2 层｜存量比率的主动/被动拆解（比率 A 的净化工序）**

比率 A 的**核心缺陷**：`流通市值 = 流通股本 × 价格`，价格下跌直接压缩分母。当融资余额↓ 且 流通市值↓ 时，只要市值跌得更快，比率**反而上升**；两者同比例下降时比率**不变**。表面上"杠杆率稳定/上升"，实际是杠杆与市值的**双双出清**。

单一存量比率无法区分**主动型上升**（分子堆积）与**被动型上升**（分母坍塌）——故须做归因：

```
Δln(R) = Δln(融资余额) − Δln(流通市值)
  ├─ 分子贡献 Δln(融资余额)   → 主动杠杆行为（融资净买入 / 净偿还）
  └─ 分母贡献 −Δln(流通市值)  → 被动价格效应（价格下跌被动推高比率）
```

判定：**只有分子驱动的存量比率上升才是真加杠杆**；分母驱动的上升是伪信号（不降权，标记"被动型·出清中"）。

**第 3 层｜两比率搭配 · 四象限联合判定（主判定表）**

把「存量水位（比率 A）」放纵轴、「流量火力（比率 B）」放横轴，四象限给出组合语义。**比率 A 必须先经第 2 层拆解（剔除分母坍塌）后再定位**：

| 存量 A ╲ 流量 B | **B 高**（融资买入占比高，杠杆在进场） | **B 低**（融资买入占比低，杠杆不参与/退场） |
| --- | --- | --- |
| **A 高**（融资余额/市值高且分子驱动） | **杠杆亢奋**：存量已重 + 还在加仓 = 风险积累最顶点 → **降权/减仓优先级最高** | **杠杆套牢**：存量重但无新增买盘，靠存量撑着 = 一旦下跌易连环强平 → **警戒，不新增**，跌破关键位优先出 |
| **A 低**（融资余额/市值低） | **杠杆入场**：存量轻 + 火力旺 = 边际增量资金进场 → **加分（景气度/技术面同向时可加仓）** | **无人区**：无杠杆资金关注 → 中性，交由基本面/技术面判定，本维不给分 |
| **A 高但分母驱动**（价跌被动推高） | **下跌中逆势加杠杆**：抄底/补仓 + 高换手 → **高风险分歧**，标注但不清算 | **去杠杆出清末期**：双降已完成、火力枯竭 → **观察反转**，不按拥挤处理（第 2 层已判伪信号） |

> **降权对应**：只有「杠杆亢奋」与「杠杆套牢」触发降权 / 警戒；「杠杆入场」加分；「无人区」中性；「去杠杆出清」不得误读为拥挤——这是单一存量比率最典型的误判场景。
|  |  |  |  |  |  |
| --- | --- | --- | --- | --- | --- |
> **实现口径**：`leverage_quadrant(retail_bal_ratio, margin_buy_ratio, price_ret_window)` → `亢奋 | 套牢 | 入场 | 无人区 | 逆势 | 出清`；`retail_bal_ratio` 须先传入已剔分母效应的 `agg_ratio_clean`（Δln 融资余额 主导），以区分「A 高·分子驱动」与「A 高·分母驱动」。两比率取滚动 5 / 20 日平滑，四象限分位切点（默认 60% / 40%）与净 / 毛口径取舍待 M1 校准（§6.2 E6）。
> **为何有效**：比率 B 是流量 ÷ 流量，天然不受价格水平污染；价格暴跌、比率 A 因分母坍塌虚高时，B 同步跌至低位，四象限落到「套牢 / 出清」而非「亢奋」。用户原定义的「融资额 / 成交量」即比率 B（毛口径），净口径（融资净买入额 / 成交额）作为可选替代。

### 4.1 因子的两种用法：横截面排序 vs 时序择时

**数据项引用关系 `dataRefs`（服务删除前占用校验）**

> 数据项不是孤立资产：删掉一个被策略或报表消费的数据项，会让下游静默失效（策略跑空、报表出错但不报错）。因此**数据项与消费方之间必须有显式登记表**，且该表是删除操作的**唯一准入依据**。

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `data` | **数据项编码**（非名称） | 须与 `data_item.id` 一致；**改名不影响本表**（见本节 ⑥）。历史按名称登记的数据须一次性迁移为编码 |
| `by` | 使用方名称 | 策略名（如「宏观四象限判定」）或报表名（如「信用脉冲月报」） |
| `kind` | `strategy` / `report` | 策略类删除会导致运行失败；报表类删除会导致结果失真，**两者同等阻止删除** |
| `note` | 用途说明 | 说明该数据项具体被用于哪个维度/计算，供删除前判断影响 |

**规则（强制）**：

1. **登记先行**：任何策略 / 报表接入新数据项时，必须同步在本表登记一行；未登记的引用视为**配置缺陷**，由 §5.4 缺口清单跟踪。
2. **删除前必查**：删除数据项前先查本表；**存在任一条引用即拒绝删除**，并列出全部占用方（含 `kind` 与 `note`），要求先解引用。
3. **不做强制删除逃生口**：不提供「忽略引用强制删除」入口——静默失效比删不掉危害更大。
4. **兜底清理**：数据项删除完成后，本表中该数据项的残留行须一并清理（正向已阻塞，此为防脏数据兜底）。
5. **采集任务不随删**：数据项与采集任务是 N:N 关系，删除单个数据项**不删除其归属任务**，任务继续采集其余数据项；仅当任务覆盖的数据项全部被删时，任务转为「空任务」并标记待处置。

**⑥ 键口径（三处关联的硬约束）**

> 数据项、引用关系、运行日志、定时任务四类对象之间靠**名称**与**编码**两张键关联。名称是人改的（可重命名），编码是机器认的（不可变），混用会造成「改名即断链」与「同名不可重名」的冲突。因此本节统一规定：

| 对象 | 主键 / 关联键 | 取值规则 | 变更语义 |
| --- | --- | --- | --- |
| 数据项 | `data_item.id`（编码）+ `name`（名称） | 编码一经创建**不可修改**（新增时由系统生成）；名称在全库**唯一**，可修改 | 改名 → 引用关系与日志**按编码自动跟随**，不产生断链 |
| 引用关系 `dataRefs` | `data` **存数据项编码**（非名称） | 对外展示时才 join 出名称 | 数据项改名无需改本表；本表出现无对应编码的行 → 视为脏数据，由删除兜底清理 |
| 运行日志 `runLogs` | `item` 字段**存数据项编码数组** | 一个任务覆盖多个数据项时存数组，不再用 `/` 拼接字符串 | 日志与数据项解耦，改名不影响历史记录的可检索性 |
| 定时任务 | `job_def.code` + `item_codes[]` | 任务与数据项为 **N:N**，由 `item_codes` 数组维护 | 删除数据项 → 从各任务 `item_codes` 移除该编码；任务不删（本节规则 5） |

**派生约束（可断言）**：

1. **删除判定**：只要存在 `dataRefs.data == 该数据项编码`，即拒删；判定必须走编码，禁止按名称比对（名称可能被改过）。
2. **日志可检索**：`runLogs.item` 含该编码即视为「该数据项相关日志」，作为删除连带清理的依据；拼接字符串写法（`A / B`）**不再接受**，历史数据须一次性迁移为数组。
3. **空任务判定**：`job_def.item_codes` 为空数组 → 任务状态为「空任务（待处置）」，在任务列表中可辨识，但**不自动删除**。
4. **一致性校验（每日）**：`dataRefs.data` 与 `job_def.item_codes[]` 中出现的编码必须全部存在于 `data_item`；存在孤儿编码 → 告警并记入 §5.4 缺口清单。

### 4.6 运行日志 `runLogs`（采集可观测性）

> 采集链路的最大风险是「**没报错但也没数据**」——源站改版、发布延迟、字段缺失都可能让任务「成功返回」却拿不到新期次。因此日志必须记录**每次运行的判定结果**，而不只是记录异常。

**① 日志字段**

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `t` | `MM-DD HH:mm` | 运行开始时间 |
| `job` | 任务名 | 如「月度发布（月末）」「日频行情（海外）」「手动增量下载」（手动补采单列一条，不并入定时任务记录） |
| `item` | 数据项 | **存数据项编码数组**（键口径见 §4.5 ⑥）；单任务多数据项时标注「N 项中 M 项成功」 |
| `type` | 异常类型 | `源站未更新` / `接口超时` / `字段缺失` 等；正常为空 |
| `res` | 执行结果 | 人可读的一句话结论，如「6 项中 5 项成功 · WTI 未落库」 |
| `lv` | 状态级别 | `null`（正常）/ `wait`（待处理）/ `done`（已恢复） |
| `retry` | 重试情况 | 次数，无则 `—` |
| `trig` | 触发方式 | `定时` / `重试` / `手动` |
| `cost` | 耗时 | 如 `12s`、`1m52s` |
| `msg` | 详细原因 | 失败/待处理的展开说明，含判定依据 |

**② 状态语义（三态，互斥）**

| `lv` | 展示 | 含义 | 是否计入待处理 |
| --- | --- | --- | --- |
| `null` | 正常 | 拿到新期次并落库，或无需更新的正常跳过 | 否 |
| `wait` | 待处理（红） | 应当拿到却没拿到（发布延迟 / 接口失败 / 字段缺失），**需人工关注** | **是** |
| `done` | 已恢复（绿） | 曾经的 `wait` 已被补数动作解决 | 否 |

**③ 补数与日志的联动规则（强制，防审计失真）**

1. **不篡改历史**：补数成功后，**禁止**把历史 `wait` 记录改写为「从未失败」；原记录保留其发生时间与原因。
2. **追加而非覆盖**：补数动作**另追加一条** `trig=手动` 的日志记录，记录补入期次与耗时，形成「失败 → 补数」的完整轨迹。
3. **状态迁移留痕**：原 `wait` 记录可迁移为 `done`，但**必须在 `msg` 中追加**「已于 HH:mm 手动增量补齐 N 期」，保留何时、如何恢复。
4. **计数口径**：「待处理」徽标 = `lv=='wait'` 的条数，**补数后应归零**；「仅异常」= `lv ∈ {wait, done}` 的历史异常总数，**补数后不减少**（历史事实不变）。

**④ 日志的保留与边界**

- 日志按数据项可检索（`item` 含该数据项即算相关），用于「删除数据项时连带清理相关日志」的判断依据（§4.5 规则 4）。
- 日志是**运行事实记录**，不是质量评分；质量告警（DL-05）另立表，二者不合并。

### 5.3 接口实测结论（可行性）

> 澄清「收盘后可得 T 日数据」：9/14 周一盘中补跑对照，结论如下。

| 接口 | 盘前(03:11)最新交易日 | 盘中(11:24)最新交易日 | 判定 |
| --- | --- | --- | --- |
| `query_kline`(个股日线) | 9/11 | **9/14 半根 bar** | 交易时段返回**当日 live 半根 bar**，15:00 后定稿 |
| `get_industry_daily`(行业) | 9/11 | **9/11（无 9/14）** | **无 live T 日 bar**，盘中停上一收盘日，仅盘后定稿 |
| 财务/行业基础/成分 | 静态全量 | 静态全量 | 非时效，随时可用 |

**结论**：

1. 个股 K线 = 「盘中半根、盘后定稿」——9:30–15:00 跑日频任务会吃未收盘半根 bar，**污染信号**；须等 15:00 后。
2. 行业日行情「盘后才出、从不给半根」，盘中查最新仍是上一收盘日 → 行业维度天然安全，但当日数据须等盘后。
3. 盘前(次日 08:00)跑拿到全为 T-1 定稿，安全但滞后一日。
4. 「T 日定稿」须排 15:00 后（如 18:00）；接受 T-1 排 08:00 也安全。

**调度规则**：

1. 每日批处理**严禁排 9:30–15:00**（盘中会吃未收盘半根 bar，污染信号）。
2. **系统默认档 = 凌晨 02:00**（次日凌晨取 T-1 全量定稿，安全不滞后过多）——对应《需求文档》**C-1 / SC-06**；管理端「数据管理 → 取数时间配置」可改，**落在 9:30–15:00 的配置拒绝保存**，变更留审计。
3. 备选档（如需 T 日定稿）可排 15:30 / 18:00；如需 T-1 亦可排次日 08:00。三档均满足「不在交易时段」硬约束。
4. 触发后 `assert` 最新交易日 == 目标日，失败告警重试（对应 SC-03）。
