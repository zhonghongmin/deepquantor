## 二、授权后的三步（沙箱侧可代做，需你授权后告知）

```bash
# 1. 建远端仓库（工蜂 API）
#    建议：私有库；默认分支 main；初始化时不加 README/.gitignore（本地已有完整骨架）

# 2. 设置远端并推送
cd D:/develop/deepquantor      # 或沙箱侧仓库目录
git remote add origin https://git.woa.com/<group>/deepquantor.git
git push -u origin main

# 3. 回验
git ls-remote origin           # 应列出 refs/heads/main
```

## 三、初始化脚本用法（Windows 本地）

```powershell
# 首次：带远端
.\scripts\init-repo.ps1 -Remote https://git.woa.com/<group>/deepquantor.git

# 已有远端仓库、先拉历史再提交
.\scripts\init-repo.ps1 -SkipInitialCommit
git pull origin main --rebase

# 幂等：已初始化则只打印提示，不重复初始化
.\scripts\init-repo.ps1
```

脚本行为：
- ✅ 校验 git 是否安装、目录是否存在
- ✅ `git init -b main` + 仅在**全局未配置时**写本地身份（不动全局配置）
- ✅ 设置 origin（已存在则跳过）
- ✅ 首次提交前**拦截误暂存的 `.env`**（凭证边界 NFR-07）
- ❌ 不改全局 git 配置、不装依赖、不删任何文件、不提交 `.env`

## 四、远端仓库应放什么 / 不放什么

**入库**：`cli/` `web/` `deploy/`（除实际 `.env`）`spec/` `migrations/` `scripts/` `README.md` CI 配置

**不入库**：
- `deploy/env/.env`（实际凭证值）—— 只提交 `.env.example`
- `cli/.venv/`、`web/node_modules/`、`.next/`
- 数据库数据目录、日志、备份（一律落 `D:\develop\<中间件>\`）
- 派生产物：设计文档 HTML 阅读版、文档中心 Hub —— **不入库**（实时渲染，仓库不是文档载体）

> 文档真值在项目资产（网盘），代码真值在 git 仓库。**同一事实只写一处**，不互相镜像。

## 五、分支与提交约定

| 分支 | 用途 |
|---|---|
| `main` | 始终可部署，CI 必绿 |
| `develop` | 集成分支 |
| `feature/<需求ID>-<简述>` | 单个需求分支（如 `feature/DL-01-统一数据提供器`） |

**分支名带需求 ID** —— 与《全量需求跟踪-2026.11.19》的编号一一对应，便于反查。

提交信息格式（Conventional Commits）：

```
<type>(<scope>): <简述>

<正文：为什么这么改 / 影响面 / 关联需求 ID>

Refs: DL-01
```

- `type`：`feat` `fix` `refactor` `test` `docs` `chore` `build` `ci`
- `scope`：`cli` `web` `spec` `deploy`
- 例：`feat(cli): 实现统一数据提供器骨架` / `fix(cli): 修正宏观资产配置四项之和校验`

## 六、PR 门禁

合并前 CI 必须全绿（`.github/workflows/ci.yml`）：

| 门禁 | 命令 | 依据 |
|---|---|---|
| spec_lint | `python scripts/spec_lint.py --spec spec/ --root .` | D-21：未 verified 不开工 |
| ruff | `ruff check .` | 编码规范 |
| pytest + 覆盖率 ≥80% | `pytest --cov=dq --cov-fail-under=80` | §9 测试体系 |
| 依赖锁一致 | `uv pip compile` + `diff` | 依赖锁防漂移 |
| tsc / eslint / vitest / build | 见 `web/package.json` | §9 测试体系 |
| 迁移回滚配对 | 每个 `migrations/*.sql` 须有同名 `.rollback.sql` | 迁移纪律 |

**代码 + 测试同 PR，CI 失败禁止合并**（`dq-deploy-skill` 的 `references/git-workflow.md` §3–§4）。

## 七、CI 首次运行需注意

`ci.yml` 中 Python 与 Node 两段用 `pip install` / `npm ci`。首次跑 CI 前需要：

```bash
cd cli && uv pip compile pyproject.toml -o requirements.lock --index-url https://pypi.tuna.tsinghua.edu.cn/simple
cd web && npm install   # 生成 package-lock.json
```

并把两个锁文件一并提交，否则 CI 的 `npm ci` 会因缺 `package-lock.json` 失败。
