# DeepQuantor 宏观主线开发复盘与交接文档

> 日期：2026-11-20 ｜ 范围：宏观月度信号链路（P10 宏观页）首次实库开发全过程

---

## 一、为什么第一次开发与预期差距大

四个根因，按严重程度排序：

### 1. 验收基准错位（视觉偏差的直接原因）
- 开发宏观页时，唯一依据是《宏观主线与展示页开发Spec.md》的文字描述；效果图 `_ref/管理端效果图.html` 一直在 `_ref/` 目录里，但**从未打开对照**。
- spec 写「当前结论区」只描述了内容（状态机、资产配置、风格偏好），没有描述布局形态 → 实现成了"文本框 + 九宫格"，而效果图是"左蓝两层状态机 hero + 右白堆叠比例条"。
- 差距直到用户贴截图才被发现——**验收时没有人比对过效果图**。

### 2. 数据源接入没有做量级体检（数据偏差的直接原因）
- 社融（TSF）主源 mofcom 因 SSL 故障被降级到金十备源 `bank_financing`，**接的时候没有验证口径**：备源月均 3000 亿，真实社融增量是月均 1~3 万亿，口径根本不是社融增量。
- 结果 127 期历史信号全部被错口径污染，信用卡折线"只有一个月是对的"（最新一期才是央行锚点新口径）。
- SSL 故障本身可修（TLS 弱 cipher 需 SECLEVEL=0 + 绕代理直连），当时定性为"站点级故障不可修"就放弃了主源，属于**降级决策太草率**。

### 3. 测试只锁契约不锁视觉
- page-spec 测试 31 项断言的全是结构关键字（空态、无百分比数值），不锁布局形态 → 测试全绿但页面长得不对。
- 数据测试 mock 了 akshare 返回，但没有对真实数据的量级/区间做 sanity check。

### 4. 开发库与实库漂移，首次上实库集中爆雷
- SQLite 测试库掩盖了 `signal.macro_signal` 的主键（signal_date vs as_of）和列类型（money_credit numeric vs VARCHAR）漂移，跑批第一次连实库才爆。
- 另有两个隐藏 bug 随实库跑批暴露：CLI 注册表双实例（`-m` 模式 `__main__`）、查询无 ORDER BY 旧期 GDP 覆盖新期。

## 二、以后怎么避免（固化流程）

| # | 规则 | 具体做法 |
|---|------|---------|
| 1 | **UI 开发"效果图先行"** | 动手前先读 `_ref/` 效果图源码，列出布局差异清单；提交前截图与效果图逐区比对，再请用户验收 |
| 2 | **数据源接入"量级体检"** | 任何指标入库前做 sanity check：同比在合理区间、月度量级与官方口径对照；不通过不得入库、不得降级灌错口径（宁可缺数） |
| 3 | **降级前先诊断** | 主源故障先定性（站点挂 vs 配置可修），SSL/代理/TLS 类问题逐一排除后再降级；降级源必须与主源同口径 |
| 4 | **DDL 唯一权威 + 实库对拍** | 表结构以 `assets/*.sql` DDL 为准；关键表加 information_schema 对拍测试，防 SQLite 掩盖漂移 |
| 5 | **逐页验收节奏** | 每完成一个页面请用户截图确认后再进下一个，不批量交付后返工 |

### 3.2 环境与运维手册

- **启动/停止**：只走本地脚本 `D:\develop\deepquantor\start-all.bat` / `stop-all.bat`（双击运行）。start-all 自带先清场再启动；PG 以 `start /min` 独立窗口拉起。**AI 会话内启动的进程会被宿主回收，不要尝试**。
- **Python**：`C:\Users\Administrator\.workbuddy\binaries\python\envs\default\Scripts\python.exe`（基础环境无依赖）。
- **数据库连接**：`postgres://postgres@127.0.0.1:5432/deepquantor`（根目录与 services/web 各有 .env）。
- **跑批命令**：`python -m dq.cli macro-monthly --window-date YYYY-MM-DD`、`macro-indicators` 同理。
- **测试**：Python 侧 `pytest tests/ -q` + `ruff check dq/ tests/`（261 项）；web 侧 `npx vitest run tests/` + `npx tsc --noEmit`（50 项），生产模式需 `npm run build` 后重启。
- **网络注意**：环境有 HTTPS_PROXY（127.0.0.1 本地代理）；mofcom 弱 cipher 站点需绕代理直连（fetchers.py 已内置 `trust_env=False`）。
