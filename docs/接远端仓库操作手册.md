## 2. 自己接远端（推荐路径，全程在你本地）

```powershell
cd D:\develop\deepquantor

# 2.1 初始化仓库 + 分支
git init -b main
git config user.name  "你的名字"          # 只作用于本仓库，不动全局配置
git config user.email "你的邮箱"

# 2.2 接远端
git remote add origin https://git.woa.com/<group>/deepquantor.git
# 若上面报 remote origin already exists，改用：
# git remote set-url origin https://git.woa.com/<group>/deepquantor.git

# 2.3 首次提交
git add -A
git status                                    # 确认没有 .env / node_modules / .venv 混进来
git commit -m "chore: 初始化仓库骨架

- Python CLI（dq 包）+ Node Web 双层目录结构
- spec/ 单一事实源、deploy/ 部署侧、migrations/ 迁移目录
- CI 门禁：spec_lint + pytest + Vitest + 迁移回滚配对检查
- .env 不入库（NFR-07）"

# 2.4 推送
git push -u origin main

# 2.5 回验
git ls-remote origin                          # 应列出 refs/heads/main
```

### 认证方式

**工蜂（推荐）**：走 HTTPS + 用户名 + 密码/PAT。若公司启用了统一认证，会跳转 SSO，用你的企业账号登录即可。

**GitHub**：密码认证已被 GitHub 禁用，必须用 PAT：
1. GitHub → Settings → Developer settings → Personal access tokens → Generate new token (classic)
2. 勾选 `repo`（读写私有库）、`workflow`（CI 配置需要）
3. 复制 token（只显示一次）
4. 推送时用户名填 GitHub 用户名，密码处粘贴 token

或用 Git Credential Manager 存起来，之后不用再输。

### 不想每次输密码 → 改用 SSH

```powershell
# 生成密钥（Windows 10+ 自带 ssh）
ssh-keygen -t ed25519 -C "your@email.com"

# 把公钥贴到平台：工蜂 → 个人设置 → SSH 公钥；GitHub → Settings → SSH keys
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub | Set-Clipboard

# 改远端地址
git remote set-url origin git@git.woa.com:<group>/deepquantor.git
git push -u origin main
```

## 3. 如果远端建库时勾了「自动创建 README」

远端会有一个独立的初始提交，与本地历史无共同祖先，`push` 会被拒：

```
! [rejected] main -> main (fetch first)
```

**二选一解决：**

**方案 A（推荐，保住远端已有内容）**：
```powershell
git pull origin main --allow-unrelated-histories
git push -u origin main
```

**方案 B（丢弃远端 README，只要本仓库内容）**：
```powershell
git push -u origin main --force
```
> ⚠️ 仅当远端除了自动 README 没有任何有价值内容时用。

### 3.1 顺带确认远端默认分支是 main

工蜂 / GitHub 建空仓库时默认分支可能是 `master`。若远端 HEAD 仍指向 `master`，
别人 clone 后会拿到「空工作区」（提示 `remote HEAD refers to nonexistent ref`）。

推送完确认一次：

```powershell
git ls-remote --symref origin HEAD
```

输出若为 `ref: refs/heads/master`，在平台上把默认分支改成 `main`
（工蜂：仓库设置 → 默认分支；GitHub：Settings → Branches → Default branch），
或本地执行：

```powershell
git remote set-head origin -a
```

## 4. 推上去之后：让 CI 跑起来

仓库已自带 `.github/workflows/ci.yml`。**注意：CI 只在 GitHub Actions 原生生效**。

| 平台 | CI 支持 | 说明 |
|---|---|---|
| **GitHub** | ✅ 原生 | 推上去即自动跑，无需配置 |
| **工蜂** | ⚠️ 需另配 | 工蜂用自有 CI 体系（`.workflow/`），需把 `ci.yml` 改写为工蜂格式，或改用外部 CI |

### 工蜂 CI 的替代做法

若用工蜂，本地跑门禁作为提交前自检：

```powershell
cd D:\develop\deepquantor

# 一致性门禁

# Python 侧
cd cli
uv venv --python 3.11
uv pip install -e ".[dev]" --index-url https://pypi.tuna.tsinghua.edu.cn/simple
ruff check .
pytest -v

# Node 侧
cd ..\web
npm install
npm run typecheck
npm run lint
npm test
npm run build
```

建议加一个 `scripts\check-all.ps1` 把上面串成一条命令（见第七节）。

## 7. 一键自检脚本（推荐加上）

在 `D:\develop\deepquantor` 建 `scripts\check-all.ps1`：

```powershell
$ErrorActionPreference = 'Stop'
$root = Split-Path -Parent $PSScriptRoot

Write-Host "=== spec_lint ===" -ForegroundColor Cyan
python "$root\scripts\spec_lint.py" --spec "$root\spec" --root $root
if ($LASTEXITCODE -ne 0) { exit 1 }

Write-Host "=== ruff ===" -ForegroundColor Cyan
Push-Location "$root\cli"
ruff check .
if ($LASTEXITCODE -ne 0) { Pop-Location; exit 1 }

Write-Host "=== pytest ===" -ForegroundColor Cyan
pytest -q --cov=dq --cov-report=term --cov-fail-under=80
if ($LASTEXITCODE -ne 0) { Pop-Location; exit 1 }
Pop-Location

Write-Host "=== web ===" -ForegroundColor Cyan
Push-Location "$root\web"
npm run typecheck; if ($LASTEXITCODE -ne 0) { Pop-Location; exit 1 }
npm test;               if ($LASTEXITCODE -ne 0) { Pop-Location; exit 1 }
Pop-Location

Write-Host "全部通过" -ForegroundColor Green
```

用 `.\scripts\check-all.ps1` 替代逐条跑。

## 8. 出问题时

| 现象 | 原因 | 处理 |
|---|---|---|
| `push` 被拒（fetch first） | 远端有独立提交 | 见第三节，`git pull --rebase --allow-unrelated-histories` |
| `Authentication failed` | PAT 过期 / 密码认证被禁 | GitHub 重新生成 PAT；工蜂确认账号权限 |
| `npm ci` 报缺 lock | `package-lock.json` 未提交 | `cd web; npm install; git add package-lock.json` |
| `uv pip compile` 很慢 / 超时 | 内网直连 PyPI 极慢 | 加 `--index-url https://pypi.tuna.tsinghua.edu.cn/simple` |
| `spec_lint` 报「未登记」 | 新增源码文件未登记 | 在 `spec/invariants.yaml → files` 补条目 |
| `spec_lint` 报「禁用词」 | 出现「主库」等受控禁用词 | 改用规范叫法；若是「禁止主库」这类否定语境说明规则需再调 |
