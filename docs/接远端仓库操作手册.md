## 2. 自己接远端（推荐路径，全程在你本地）

```powershell
cd D:\develop\deepquantor

# 2.1 初始化仓库 + 分支

# 2.2 接远端
git remote add origin https://git.woa.com/<group>/deepquantor.git
# 若上面报 remote origin already exists，改用：
# git remote set-url origin https://git.woa.com/<group>/deepquantor.git

# 2.3 首次提交
git add -A
git status                                    # 确认没有 .env / node_modules / .venv 混进来
git commit -m "chore: 初始化仓库骨架

- Python CLI（dq 包）+ Node Web 双层目录结构
- spec/ 单一事实源、deploy/ 部署侧、migrations/ 迁移目录

- .env 不入库（NFR-07）"

# 2.4 推送
git push -u origin main

# 2.5 回验
git ls-remote origin                          # 应列出 refs/heads/main
```

### 认证方式

**工蜂（推荐）**：走 HTTPS + 用户名 + 密码/PAT。若公司启用了统一认证，会跳转 SSO，用你的企业账号登录即可。

**GitHub**：密码认证已被 GitHub 禁用，必须用 PAT：
1. GitHub → Settings → Developer settings → Personal access tokens → Generate new token (classic)
2. 勾选 `repo`（读写私有库）、`workflow`（CI 配置需要）
3. 复制 token（只显示一次）
4. 推送时用户名填 GitHub 用户名，密码处粘贴 token

或用 Git Credential Manager 存起来，之后不用再输。

### 不想每次输密码 → 改用 SSH

```powershell
# 生成密钥（Windows 10+ 自带 ssh）
ssh-keygen -t ed25519 -C "your@email.com"

# 把公钥贴到平台：工蜂 → 个人设置 → SSH 公钥；GitHub → Settings → SSH keys
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub | Set-Clipboard

# 改远端地址
git remote set-url origin git@git.woa.com:<group>/deepquantor.git
git push -u origin main
```

## 3. 如果远端建库时勾了「自动创建 README」

远端会有一个独立的初始提交，与本地历史无共同祖先，`push` 会被拒：

```
! [rejected] main -> main (fetch first)
```

**二选一解决：**

**方案 A（推荐，保住远端已有内容）**：
```powershell
git pull origin main --allow-unrelated-histories
git push -u origin main
```

**方案 B（丢弃远端 README，只要本仓库内容）**：
```powershell
git push -u origin main --force
```
> ⚠️ 仅当远端除了自动 README 没有任何有价值内容时用。

### 3.1 顺带确认远端默认分支是 main

工蜂 / GitHub 建空仓库时默认分支可能是 `master`。若远端 HEAD 仍指向 `master`，
别人 clone 后会拿到「空工作区」（提示 `remote HEAD refers to nonexistent ref`）。

推送完确认一次：

```powershell
git ls-remote --symref origin HEAD
```

输出若为 `ref: refs/heads/master`，在平台上把默认分支改成 `main`
（工蜂：仓库设置 → 默认分支；GitHub：Settings → Branches → Default branch），
或本地执行：

```powershell
git remote set-head origin -a
```

## 8. 出问题时

| 现象 | 原因 | 处理 |
|---|---|---|
| `push` 被拒（fetch first） | 远端有独立提交 | 见第三节，`git pull --rebase --allow-unrelated-histories` |
| `Authentication failed` | PAT 过期 / 密码认证被禁 | GitHub 重新生成 PAT；工蜂确认账号权限 |
| `npm ci` 报缺 lock | `package-lock.json` 未提交 | `cd web; npm install; git add package-lock.json` |
| `uv pip compile` 很慢 / 超时 | 内网直连 PyPI 极慢 | 加 `--index-url https://pypi.tuna.tsinghua.edu.cn/simple` |
| `spec_lint` 报「未登记」 | 新增源码文件未登记 | 在 `spec/invariants.yaml → files` 补条目 |
| `spec_lint` 报「禁用词」 | 出现「主库」等受控禁用词 | 改用规范叫法；若是「禁止主库」这类否定语境说明规则需再调 |
| 推送报 `Permission denied (publickey)` | 沙箱重建，私钥随沙箱丢失 | 见 8.1，**从项目资产恢复同一把 Deploy Key**，不要重新生成 |
| 新会话不知道仓库地址 / 从哪开始 | 缺少发现路径 | 见 8.1 冷启动协议：`search_content` 搜短词「Git凭据托管说明」→ 取 file_id → 恢复 → clone |
| `search_content` 搜不到 | query 太长（语义检索对长句失配） | 换成文档标题里的**短词**重搜 |
| `search_file` 报缺 dir_id | 该工具强制限定目录，冷启动无 id | 改用 `search_content` 全盘搜，或从注册表取 id |
| 直链下载 403 | 人工转写 1600+ 字符签名串出错 | 用 `scripts/tdrive_fetch.py --json` 下载；403 的第一嫌疑是转写错，不是过期 |

### 8.1 冷启动：其他会话如何找到本仓库并恢复凭据

> 本节回答一个具体问题：**一个新会话（什么都不知道、沙箱全新）怎么找到这里？**
> 2026-11-18 实测跑通：清空 `/root/.ssh` 与 `/workspace` 下所有本地线索，
> 只留 `codebuddy.md`，按下面的协议完整走通 → 装回凭据 → clone 成功。

#### 冷启动协议（5 步，不依赖任何既有文件）

```
① search_content 搜短词「Git凭据托管说明」  → 拿 file_id（启动页）
② file_download 托管说明                    → 得仓库地址、私钥 file_id、指纹
③ file_download 私钥 + 恢复脚本             → 两个文件（脚本网盘有副本）
④ 装私钥：bash restore-git-credential.sh --from-file <私钥>
⑤ git clone git@github.com:zhonghongmin/deepquantor.git
```

**第 ① 步的要点**：

- 用 `mcp__netdrive__tdrive.search_content`，**不传 `dir_id`** = 全盘搜。
- **query 必须是短词**（就用文件名「Git凭据托管说明」）。
  实测长自然语言 query（"Git凭据托管说明 仓库地址 私钥 file_id 指纹"）**返回空 hits**。
- `search_file` **强制要求 `dir_id`**，冷启动阶段没有 id，用不了。

**第 ③ 步的要点**：恢复脚本在网盘 `.agent-credentials/` 留了副本，专门用来打断
「要 clone 才有脚本 → 要脚本装凭据 → 要凭据才能 clone」的循环。
网盘副本与仓库 `scripts/restore-git-credential.sh` 字节一致。

**第 ⑤ 步的要点**：clone 之后若要提交，先确认 git 身份已配置
（沙箱全新时 `~/.gitconfig` 也是空的，会报 `Author identity unknown`）：

```bash
git config --global user.name  "WorkBuddy Agent"
git config --global user.email "agent@deepquantor.local"
```

**备用腿**（技能目录被平台托管时可用）：

```bash
python3 -c "import json;d=json.load(open('/root/.codebuddy/skills/dq-doc-manage-skill/assets/doc_center_assets.json'));print(json.dumps(d['agent_credentials'],ensure_ascii=False,indent=1))"
```

该注册表含 `dir_id`、各 `file_id`、`repo`、`fingerprint`。

#### 恢复凭据（拿到私钥之后）

沙箱是**易失载体**：休眠唤醒会保留，但整体重建后 `/root/.ssh` 会丢，私钥没了。
**GitHub 侧的公钥记录不受影响**（它是独立存储）。

```bash
# 1. agent 用 MCP 签发网盘直链（file_id 见《Git凭据托管说明》）
#    mcp__netdrive__tdrive.file_download { file_id: "<私钥 file_id>" }
# 2. 交给恢复脚本安装并验证
bash scripts/restore-git-credential.sh --from-file <下载的私钥路径>
# 或直接给 URL：
bash scripts/restore-git-credential.sh "<download_url>"

# 只体检不改动：
bash scripts/restore-git-credential.sh --check
```

脚本会：先验内容再安装（拦截 XML 错误体）→ 覆盖 `~/.ssh/config` 保证只有一把 key
→ 认证验证 → 识别密钥类型（Deploy Key / 账号级）。

> 直链有效期约 60 分钟且是一次性的，**签发后立即使用**；失效就重新签发，不要缓存。
> 直链是 1600+ 字符的签名串，人工转写极易出错 —— **用 `scripts/tdrive_fetch.py` 下载，
> 不要手打 curl**。

**备用路径：重新生成密钥（仅当 Deploy Key 也被删除时）**

```bash
mkdir -p /root/.ssh && chmod 700 /root/.ssh
ssh-keygen -t ed25519 -N "" -C "deepquantor-deploy" -f /root/.ssh/id_ed25519_dq_deploy
cat /root/.ssh/id_ed25519_dq_deploy.pub     # ← 复制这一行，加到仓库 → Settings → Deploy keys

cat > /root/.ssh/config <<'EOF'
Host github.com
    HostName github.com
    User git
    IdentityFile /root/.ssh/id_ed25519_dq_deploy
    IdentitiesOnly yes
    StrictHostKeyChecking accept-new
EOF
chmod 600 /root/.ssh/config
ssh -T git@github.com     # 期望输出：Hi <user>/<repo>! You've successfully authenticated...
```

> **用仓库级 Deploy Key，不用账号级 SSH Key。** 账号级 key 对该账号**所有仓库**有权限，
> 而托管它等于把整个账号的仓库访问权放进一个文件；Deploy Key 权限仅锁定单个仓库。
> 判定方法：认证输出含 `Hi <user>/<repo>!` 即为 Deploy Key，只有 `Hi <user>!` 才是账号级。
>
> 恢复后照旧 `bash scripts/push-github.sh` 即可。
>
> **真正持久的载体是 git 仓库与项目资产，不是沙箱** —— 代码在 GitHub、文档与私钥在网盘，
> 沙箱全丢也能完整重建。
