### 2.1 调度脚本契约（WorkBuddy 只触发，脚本执行）

职责边界：WorkBuddy 平台只按 cron 发一条命令行，**不含任何业务逻辑**；取数、计算、策略判定全部在 CLI 脚本内。禁止在平台侧实现业务、绕过 CLI 直写业务库、同步执行日志原文到线上库。

| 项 | 规格 |
| --- | --- |
| 任务定义唯一权威 | `deploy/scheduler/jobs.yaml`：`job_key` / `cli_command` / `cron` / 超时 / 重试 |
| 登记脚本 | `register_jobs.py` 幂等写 `task.job_def`，回写 `automation_id`；cron 落 09:30–15:00 → 退出码 2 |
| 触发命令 | `python -m dq.cli <job_key> --window-date YYYY-MM-DD --run-id <uuid>`，venv 内绝对路径 |
| 宏观分频任务 | `macro-daily` 日频辅助 02:00 跳过非交易日；`macro-monthly` cron `0 10 10-20 * *`，发布窗口内取上月、取到即停 |
| 状态回写 | CLI 结束自写 `task.job_instance`（状态 / 退出码 / 耗时 / 日志摘要），不依赖平台回调 |
| 并发与超时 | 同一 `job_key` 平台侧单实例串行、跨任务并行；超时按 `job_def` kill 子进程并记失败 |
| 兜底 | 平台不可用则线下手工执行 CLI，必告警留痕；恢复后不自动重放已手工执行的批次 |
| 配置纪律 | cron 与守卫只写在 `jobs.yaml` 与平台侧，CLI 内不重复硬编码时点；变更走 `#datamgmt` 定时任务 Tab 留审计并同步 `jobs.yaml` |

> 出场顺序：`register_jobs.py` 写 `job_def` → 平台建任务填命令 + cron 回写 `automation_id` → 手动触发核对 `job_instance` → 打开定时。调度字段统一 `automation_id` / `automation_run_id`（B13）。出处：《环境与初始化文档》§4/§7.1/§8、《系统设计总文档》§5.3。

## 3. 数据契约（先冻结，再开发）

`MacroSignal` 为宏观唯一输出契约，字段以《数据策略总文档》§1.7 JSON 为准。开发前先落成 JSON Schema，作为 MC-05 与所有展示页的共用断言。强约束：

| 约束 | 断言 |
| --- | --- |
| 五项资产 | `asset_alloc` 五项和 = 1.0，`stock == equity_weight`，含 `commodity` 且本期 = 0.0 |
| 仓位有界 | `equity_weight ∈ [0,1]`；`phase ∈ {前期,后期}`；`phase_progress ∈ [0,1]` |
| 字段正交 | `regime` 与 `money_credit` 互不推导；`factors` 仅四因子，无 `rate` |
| 资金口径 | `money_detail` 只含 `volume`/`month`；DR001 零输入，无 `price`/`dr001*` |
| 信用口径 | `credit_detail` 只凭 `afre_yoy`+`ml_loan_yoy`；`factors.credit == credit_detail.volume` |
| 只读派生 | `forecast_signals.hit_rate_status` 未回测只能 `pending`，不写回信号 |
| 快照一致 | `factors.growth == growth_verified.pmi_state`；GDP 不反写 |

## 5. 管理端页面（前端，按页交付）

技术：单一 Next.js 应用内，每页 = 侧栏 `data-p` + `<section id>` + `titles` 三处同源。布局与交互以《管理端效果图》对应锚点为唯一载体，本 Spec 只列数据源与验收。

所有列表实现**空 / 加载 / 错误 / 无权限**四态，缺数据不编造兜底值。

| 页面 | 路由·需求 | 只读数据源 | 验收（可判定） |
| --- | --- | --- | --- |
| 投资建议 | `#advice`·AD-08 | `MacroSignal` 的 `regime`/`asset_alloc`/结论 | 1440×900 首屏不滚动可见周期名 + 占比条 + 结论条；本页 4 张维度卡/6 月折线/5 年回溯图出现数 = 0；五项占比合计 100% 且股票 = `equity_weight`；「查看宏观数据 →」≤1 次点击达 `#macro` |
| 宏观数据 | `#macro`·AD-10 | `MacroSignal` + 月/季频指标 + `forecast_signals` + 5 年时序 | 实现四区，周期判定区 DR001 输入 = 0；4 张卡各 1 条折线、期数 = 6，补零/前值填充即失败，中间缺失断开；`warn_flags`/`macro_aux_signal` 产出 = 0 且预警区标注 D-30；预测信号命中率未回测显示「待回测」；回溯图标「示例数据 · 虚构」且不参与判定 |
| 概览 | `#overview`·AD-09 | `data_item` + 元数据汇总 | 一屏见三层卡；L1 计数与运维监控同源一致；健康标签三档按待补期数判定正确；接口失败显骨架重试、不显 0 值；L2/L3 恒灰态 |
| 运维监控 | `#monitor`·AD-02 | 宏观数据项清单（15 项口径见 §1.2） | 逐项显示库内期次/官方可获取期次/待补/状态；增量下载只拉缺失期、未发布期跳过且原值不变；刷新元数据不触发采数 |
| 数据管理 | `#datamgmt`·AD-02 | 数据项表 + 任务状态表 | 数据项增删改查即时生效且留审计；被引用数据项删除被拒且数据不变，未引用者删除后数据与日志同清；cron 落交易时段被拒；补跑缺区间/缺类型被拒、跑两次结果一致 |

> 四态结构断言、字段白名单裁剪、11 页 = 11 section = 11 导航 = 11 路由键，纳入 `spec_lint`。`#advice` 与 `#macro` 结论与数据分离，重复区块判 `#macro` 迁移未完成。

## 6. 依赖编排与隔离铁律

| 类别 | 规则 |
| --- | --- |
| 调度 DAG | `job-macro` 采数 → MC 判定 → 落库（同步为后置项，本期截止到落库）；上游失败 → 下游 `skipped`，状态与原因写任务状态表 |
| 跨层隔离 | 宏观失败不阻断微观；微观批次成功/失败两种情形下 `macro_signal` 快照哈希必须一致 |
| 范畴隔离 | `money_credit` 九宫格只渲染流动性状态，格内不得出现周期名；DR001 不入判定 |
| 只读铁律 | `forecast_signals`、`macro_detail` 不反写 `factors`/`equity_weight`/`confidence` |
